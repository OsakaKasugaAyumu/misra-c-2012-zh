被赋值（Assigned）

如果表达式是赋值所作用的对象，就称该表达式被赋值。

赋值（Assignment）

有时用“赋值”一词指称任何按赋值方式进行的操作会比较方便。该词涵盖以下操作：

  • 使用赋值运算符之一进行赋值；
  • 向函数传递实参，此时实参的值如同通过赋值一样被复制到相应的形参；
  • 从函数返回一个表达式，此时该表达式的值如同通过赋值一样被复制到一个具有该函数返回类型的对象中；
  • 使用表达式初始化对象的全部或一部分（包括 C99 中的复合字面量），此时表达式的值如同通过赋值一样被复制到目的对象。

代码（Code）

代码由翻译单元中未被条件编译排除的所有内容组成。

死代码（Dead code）

凡是结果不影响程序行为的操作，都是死代码。

注：初始化不等同于赋值运算，因此不属于可能被判为死代码的操作。

死代码的例子包括：

  • 将值存入此后始终不会用到的非 volatile 对象；
  • 不向对象赋值的表达式语句。

以下操作绝不是死代码：

  • 访问 volatile 对象；
  • 使用语言扩展。

在嵌入式程序中，动作发生的时间通常是其行为的一个重要方面。因此，起插入延时作用的代码不是死代码。不过，这类代码很可能要用到定时器硬件，因而无论如何都会涉及对 volatile 对象的访问。例如：

extern const volatile uint16_t MILLISEC_TIMER;

void delay_ms ( uint16_t n )
{
  uint16_t  start_time = MILLISEC_TIMER;

  while ( ( MILLISEC_TIMER - start_time ) < n )
  {
    /* wait */
  }
}

原书代码注释中译：等待。

外部标识符（External identifier）

外部标识符是具有外部链接属性的标识符，因此它必定表示对象或函数。

头文件（Header file）

凡是 #include 指令所包含的文件就是头文件。

注：文件的扩展名无关紧要。

内联函数（Inline function）

用函数说明符 inline 声明的函数是内联函数。

循环计数器（Loop counter）

循环计数器的定义见 §8.14。

宏标识符（Macro identifier）

宏标识符是作为宏名或宏形参的标识符。

不透明类型（Opaque type）

不向使用者提供实现细节的类型。

持久副作用（Persistent side effect）

如果一个副作用可能影响执行过程中某一点的执行状态，就称该副作用在该点是持久的。就程序中的某一给定点而言，以下副作用均为持久副作用：

  • 修改文件；
  • 修改对象；
  • 访问 volatile 对象。

调用函数可能产生副作用。从调用方来看，修改文件或访问 volatile 对象是持久的。但是，如果被调函数修改了某些对象，而在它返回时这些对象的生存期已经结束，它们就不影响调用方的执行状态。对调用方而言，修改这些对象所产生的副作用不是持久的。

例如：

uint16_t f ( void )
{
  uint16_t  temp = 1;           /* Side effect of modifying temp is not
                                 * persistent to the caller */

  return ( temp );
}

x = f ( );

原书代码注释中译：修改 temp 的副作用对调用方而言不是持久的。

项目（Project）

一个项目的代码来自用以构建一个可执行文件的一组翻译单元。典型的嵌入式控制器可能包含若干个在逻辑上相互独立的项目，例如：

  • 一级引导加载程序；
  • 二级引导加载程序；
  • 主应用程序。

原型形式（Prototype form）

如果一个函数类型包含原型，就称它采用原型形式；也就是说，它列出了形参类型，也可以给出形参名。例如，以下声明均采用原型形式：

void  f ( void );            /* Prototype specifying no parameters      */
void  g ( int16_t, char );   /* Prototype specifying types but no names */
void  h ( uint32_t n );      /* Prototype specifying type and name      */

原书代码注释中译：原型指明没有形参；原型指明类型而未给名称；原型同时指明类型和名称。

以下写法则不采用原型形式：

void      f ( );                /* No information about parameters      */

void g ( x, y )                 /* Function definition "K&R"-style      */
int16_t x;
char y;
{
}

原书代码注释中译：没有提供形参信息；采用“K&R”风格的函数定义。

标准类型（Standard type）

表达式的标准类型，是按 C 语言标准确定的该表达式的类型。

不可达代码（Unreachable code）

如果在没有硬件故障且忽略未定义行为影响的情况下，不存在能使一段代码得到执行的程序输入组合，则这段代码不可达。

不可达代码可能源于程序控制流图的结构。例如，return 语句之后的代码都不可达；逻辑运算符或条件运算符的一些操作数也可能不可达：

uint16_t  y;

uint16_t f ( void )
{
  uint16_t  x;

  return true ? y : ( y + 1U );    /* y + 1 is never executed     */
  x = 10U;                         /* statement is never executed */
}

原书代码注释中译：y + 1 永不执行；这条语句永不执行。

即使存在到达某条语句的控制流路径，如果这条路径绝不可能被走到，也会出现不可达代码。例如：

uint16_t  x, y;

switch ( 2u * x )
{
case 0:
  y = 10u;
  break;
case 1:
  y = 0u;   /* unreachable: 2 * x can never be odd */
  break;

case 2:
  y = x;
  break;
default:
  break;
}

原书代码注释中译：不可达：2 * x 不可能是奇数。

被使用（Used）

当一个表达式出现在以下任一上下文中时，就称该表达式被使用：

  • 作为运算符的操作数，包括作为函数调用运算符的参数；
  • 作为 if、while、for、do … while 或 switch 语句的控制表达式；
  • 作为 return 语句返回的值；
  • 作为初始化器。

不应将这个术语与读取对象的值混为一谈。例如：

uint16_t  x = 3;
uint16_t *p = &x;               /* x is used but not read */

return *p;                      /* x is read but not used */

原书代码注释中译：x 被使用但没有被读取；x 被读取但没有被使用。
