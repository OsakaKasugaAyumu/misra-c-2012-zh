Rule 1.1 · 语法、约束与翻译限度

底本定位 §8.1 · PDF 45–46／印刷 37–38

原文译文

8　规则

8.1　标准 C 环境

Rule 1.1　程序不得违反标准 C 的任何语法规则或约束，也不得超出实现的翻译限度。

[MISRA Guidelines 表 3]，[IEC 61508-7：表 C.1]，[ISO 26262-6：表 1]

类别
必需（Required）
分析
可判定（Decidable），单一翻译单元（Single Translation Unit）
适用标准
C90、C99

进一步说明

程序必须只使用所选标准版本规定的 C 语言及其库的特性（见 §3.1）。

标准允许实现提供语言扩展，本规则也允许使用这样的扩展。

除使用语言扩展的情形外，程序不得：

  • 违反标准描述的任何语言语法规则；
  • 违反标准施加的任何约束。

程序不得超出实现规定的翻译限度。标准规定了翻译限度的最低要求，但实现可以提供更高的限度。

注： 符合标准的实现会为语法或约束违规产生诊断，但须注意：

  • 诊断不一定是错误，例如也可以是警告；
  • 即使存在语法或约束违规，程序仍有可能被翻译并生成可执行文件。

注： 超出翻译限度时，符合标准的实现无须产生诊断；它可能生成可执行文件，但不保证该文件能正确执行。

理由

制定这些准则时，没有考虑受支持的 ISO/IEC 9899 版本之外的语言特性所涉及的问题。

有个案表明，某些不符合标准的实现未能诊断出约束违规；例如 [38] 第 135 页示例 2，题为“写入 const 区域的错误”。

原书示例

一些 C90 编译器通过 __inline 关键字支持内联函数。如果一个使用 __inline 的 C90 程序原本就是要用这样的编译器来翻译的，那么它符合本规则。

许多面向嵌入式目标的编译器提供额外的关键字，用于按对象所在存储区域的属性限定对象类型，例如：

  • __zpage —— 可以用一条短指令访问对象；
  • __near —— 16 位就能存放指向对象的指针；
  • __far —— 24 位就能存放指向对象的指针。

只要编译器将这些关键字作为语言扩展予以支持，使用它们的程序就符合本规则。
