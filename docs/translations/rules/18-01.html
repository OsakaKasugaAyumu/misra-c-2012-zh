Rule 18.1 · 数组元素、尾后指针与子数组边界

底本定位 PDF／印刷 151–153／143–145。

原文译文

§8.18　指针与数组

Rule 18.1　对指针操作数进行算术运算所得的指针，必须指向与该操作数所指元素属于同一数组的元素。

C90 [未定义 30]；C99 [未定义 43、44、46、59]

类别
必需（Required）
分析
不可判定（Undecidable），系统（System）
适用标准
C90、C99

进一步说明

C 标准明确定义了形成指向数组末元素之后一个位置的指针的行为，本条也允许形成这样的指针。对这个尾后指针解引用会导致未定义行为，本条禁止这样做。

本条适用于所有下列数组索引形式：

integer_expression + pointer_expression
pointer_expression + integer_expression
pointer_expression - integer_expression
pointer_expression += integer_expression
pointer_expression -= integer_expression
++pointer_expression
pointer_expression++
--pointer_expression
pointer_expression--
pointer_expression [ integer_expression ]
integer_expression [ pointer_expression ]

注： 子数组本身也是数组。

注： 就指针算术而言，对于不属于任何数组的对象，C 标准将其视为只有一个元素的数组（C90 第 6.3.6 节，C99 第 6.5.6 节）。

理由

有些编译器或许能在编译时发现越过数组边界的情况，但通常不会在运行时检查数组下标是否有效。使用无效下标可能导致程序行为错误。

最值得关注的是在运行时才得出的下标值，因为静态分析或人工审查都不容易核查这些值。只要有可能且切实可行，就应编写防御性代码，检查这类下标是否属于有效取值，并在必要时采取适当行动。

如果上述任何表达式的结果既不指向 pointer_expression 所指数组的某个元素，也不指向该数组末元素之后的一个位置，行为就未定义。详见 C90 第 6.3.6 节和 C99 第 6.5.6 节。

多维数组是“数组的数组”。本条不允许指针运算的结果指向另一个子数组。不得用下标跨越数组的“内部”边界，因为这种行为未定义。

原书示例

使用 + 运算符还会违反 Rule 18.4。

int32_t f1 ( int32_t * const a1, int32_t a2[ 10 ] )
{
  int32_t *p = &a1[ 3 ];        /* Compliant/non-compliant depending on
                                 * the value of a1                       */
  return *( a2 + 9 );           /* Compliant                             */
}

void f2 ( void )
{
  int32_t data = 0;
  int32_t b = 0;
  int32_t c[ 10 ] = { 0 };
  int32_t d[ 5 ][ 2 ] = { 0 }; /* 5-element array of 2-element arrays
                                * of int32_t                             */

int32_t *p1 = &c[ 0 ];         /* Compliant                              */

int32_t *p2 = &c[ 10 ];        /* Compliant - points to one beyond       */

int32_t *p3 = &c[ 11 ];        /* Non-compliant - undefined, points to
                                *                 two beyond             */
data = *p2;                    /* Non-compliant - undefined, dereference
                                *                 one beyond             */

data = f1 ( &b, c );
data = f1 ( c, c );

p1++;                          /* Compliant                              */
c[ -1 ] = 0;                   /* Non-compliant - undefined, array
                                *                 bounds exceeded        */
data = c[ 10 ];                /* Non-compliant - undefined, dereference
                                *                 of address one beyond  */
data = *( &data + 0 );         /* Compliant     - C treats data as an
                                *                 array of size 1        */

d[ 3 ][ 1 ] = 0;               /* Compliant                              */
data = *( *( d + 3 ) + 1 );    /* Compliant                              */
data = d[ 2 ][ 3 ];            /* Non-compliant - undefined, internal
                                *                 boundary exceeded      */

p1 = d[ 1 ];                   /* Compliant                              */
data = p1[ 1 ];                /* Compliant     - p1 addresses an array
                                *                 of size 2              */
}

原书代码注释中译（依次）： （1）是否合规取决于 a1 的值。 （2）合规。 （3）一共有五个元素，每个元素又是由两个 int32_t 组成的数组。 （4）合规。 （5）合规：指向尾后一个位置。 （6）不合规：未定义，指向末元素之后第二个位置。 （7）不合规：未定义，对尾后指针解引用。 （8）合规。 （9）不合规：未定义，越过数组边界。 （10）不合规：未定义，对尾后地址解引用。 （11）合规：C 将 data 当成长度为 1 的数组。 （12）合规。 （13）合规。 （14）不合规：未定义，越过内部边界。 （15）合规。 （16）合规：p1 所指的数组有两个元素。

下例说明对结构体成员进行的指针算术。每个成员本身都是独立的对象，所以本条不允许用指针算术从一个成员移到下一个成员。不过，只要所得指针仍在该成员对象的边界内，本条并不禁止对指向它的指针进行算术运算。

struct
{
  uint16_t x;
  uint16_t y;
  uint16_t z;
  uint16_t a[ 10 ];
} s;

uint16_t *p;

void f3 ( void )
{
  p = &s.x;
  ++p;         /* Compliant     - p points one beyond s.x                */
  p[ 0 ] = 1;  /* Non-compliant - undefined, dereference of address one
                *                 beyond s.x which is not necessarily
                *                 the same as s.y                        */
  p[ 1 ] = 2;  /* Non-compliant - undefined                              */

p = &s.a[ 0 ]; /* Compliant     - p points into s.a                      */
p = p + 8;     /* Compliant     - p still points into s.a                */
p = p + 3;     /* Non-compliant - undefined, p points more than one
                *                 beyond s.a                             */
}

原书代码注释中译（依次）： （1）合规：p 指向 s.x 的尾后位置。 （2）不合规：未定义，对 s.x 的尾后地址解引用；此地址不一定与 s.y 的地址相同。 （3）不合规：行为未定义。 （4）合规：p 指向 s.a 内部。 （5）合规：p 仍指向 s.a 内部。 （6）不合规：未定义，p 已越过 s.a 的尾后位置。
