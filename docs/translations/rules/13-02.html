Rule 13.2 · 求值顺序、别名与持久副作用

底本定位 规则 PDF／印刷 117–118／109–110。

原文译文

Rule 13.2　在所有允许的求值顺序下，表达式的值及其持久副作用都必须相同。

C90 [未指定 7–9；未定义 18]；C99 [未指定 15–18；未定义 32]

类别
必需（Required）
分析
不可判定（Undecidable），系统（System）
适用标准
C90、C99

进一步说明

在任意两个相邻的序列点之间，或在任一完整表达式之内：

  1. 不得多次修改同一对象；
  2. 不得既修改又读取同一对象，除非对该对象值的每次读取都用于计算要存回该对象的值；
  3. 以 volatile 限定类型进行的修改访问，合计不得超过一次；
  4. 以 volatile 限定类型进行的读取访问，合计不得超过一次。

注： 表达式既可能直接访问对象，也可能通过指针或被调用函数间接访问对象。

注： 本段进一步说明有意比规则主句更严格。例如，下列表达式：

x = x = 0;

不为本规则所允许，即使在 x 不具有 volatile 限定的前提下，表达式的值及其持久副作用均与求值顺序或副作用的发生顺序无关。

C90 和 C99 标准各自的附录 C 均汇总了序列点。C90 的序列点是 C99 序列点的子集。

完整表达式的定义见 C90 标准 §6.6 及 C99 标准 §6.8。

理由

C 标准在表达式求值上给编译器相当大的自由。大多数运算符的操作数可以按任意顺序求值。主要例外如下：

  • 逻辑与 &&：仅当第一操作数求值为非零时才求第二操作数的值；
  • 逻辑或 ||：仅当第一操作数求值为零时才求第二操作数的值；
  • 条件运算符 ?:：总是先求第一操作数的值，随后只对第二或第三操作数中的一个求值；
  • 逗号运算符 ,：先求第一操作数的值，再求第二操作数的值。

注： 括号可能改变运算符的作用顺序，但并不改变最底层各操作数可以任意顺序求值这一点。

遵循 Rule 13.3 和 Rule 13.4 的建议，可以避免许多常见的、与表达式求值有关的不可预测行为。

原书示例

在下列不符合本规则的示例中，调用宏 COPY_ELEMENT 时，i 被读取两次、修改两次。对 i 的操作按以下哪种顺序发生，未作指定：

  • 读、修改、读、修改；或者
  • 读、读、修改、修改。
#define COPY_ELEMENT ( index ) ( a[( index )] = b[( index )] )

COPY_ELEMENT ( i++ );

在下列不符合本规则的示例中，读取 v1 和 v2 的顺序未指定。

extern volatile uint16_t v1, v2;
uint16_t t;

t = v1 + v2;

在下列符合本规则的示例中，PORT 被读取并被修改。

extern volatile uint8_t PORT;

PORT = PORT & 0x80u;

下列不符合本规则的示例表明，函数实参的求值顺序与副作用发生的顺序均未指定。

uint16_t i = 0;

/*
 * Unspecified whether this call is equivalent to:
 *      f ( 0, 0 )
 * or   f ( 0, 1 )
 */
f ( i++, i );

函数指示符与函数实参的相对求值顺序未指定。在下列不符合本规则的示例中，如果调用 g 会修改 p，则函数指示符 p->f 使用的是调用 g 之前还是之后的 p 值，未作指定。

p->f ( g ( &p ) );

另见

Dir 4.9、Rule 13.1、Rule 13.3、Rule 13.4。

原书代码注释中译（按出现顺序）： 实参示例的底本注释称，未指定此次调用相当于 f ( 0, 0 ) 还是 f ( 0, 1 )。这是原注释所列的两种情形，不是可据以运行反例的结果保证。

源页核对： PDF 118：页图中 COPY_ELEMENT 与左括号之间确有空格，按字面不是函数式宏定义，而正文描述的是传参调用，保留两者不擅改。同页将 f(i++, i) 的可能实参写成两组；同一序列点区间对 i 的修改与无关读取会产生未定义行为，并非只能得到这两组值。原书片段不运行。
