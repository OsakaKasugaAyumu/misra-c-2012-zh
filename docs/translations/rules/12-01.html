Rule 12.1 · 运算符优先级与括号

8.12　表达式

Rule 12.1　应明确表示表达式中运算符的优先级。

类别
建议（Advisory）
分析
可判定（Decidable），单一翻译单元（Single Translation Unit）
适用标准
C90、C99

进一步说明

本规则的定义使用下表。

说明运算符或操作数优先级
基本表达式标识符、常量、字符串字面量、( 表达式 )16（高）
后缀[]　()（函数调用）　.　->　++（后置自增）　--（后置自减）　() {}（C99：复合字面量）15
一元++（前置自增）　--（前置自减）　&　*　+　-　~　!　sizeof　defined（预处理器）14
强制转换()13
乘法类*　/　%12
加法类+　-11
按位移位<<　>>10
关系<　>　<=　>=9
相等==　!=8
按位与&7
按位异或^6
按位或|5
逻辑与&&4
逻辑或||3
条件?:2
赋值=　*=　/=　%=　+=　-=　<<=　>>=　&=　^=　|=1
逗号,0（低）

表中选用的优先级是为了简明地描述本规则，不一定与其他资料描述运算符优先级时使用的级别相同。

就本规则而言，表达式的优先级是该表达式解析树的根元素（操作数或运算符）的优先级。

例如，表达式 a << b + c 的解析树可以表示如下：

     <<
    /  \
   a    +
       / \
      b   c

这棵解析树的根元素是 <<，因此该表达式的优先级为 10。

建议如下：

  • sizeof 运算符的操作数应括在圆括号内；
  • 对于优先级在 2 至 12 范围内的表达式，凡同时满足以下两个条件的操作数，均应加圆括号：
    • 操作数的优先级小于 13，并且
    • 操作数的优先级高于该表达式的优先级。

理由

C 语言的运算符较多，它们之间的相对优先级并不直观，经验较少的程序员因此可能犯错。用圆括号明示运算符优先级，可以排除程序员对优先级抱有错误预期的可能，也能让审查者和维护者看清原程序员的意图。

另一方面，过多的圆括号会使代码杂乱，降低可读性。本规则旨在两种难读的写法之间取得平衡：一种括号太多，另一种括号太少。

原书示例

下例中，一元或后缀运算符的操作数或者是基本表达式，或者是顶层运算符优先级为 15 的表达式。

a[ i ]->n;      /* Compliant - no need to write ( a[ i ] )->n          */
*p++;           /* Compliant - no need to write *( p++ )               */
sizeof x + y;   /* Non-compliant - write either sizeof ( x ) + y
                 * or sizeof ( x + y )                                 */

以下表达式中的运算符处于同一优先级。这些写法均符合本规则；不过，视 a、b 和 c 的类型而定，含有多个运算符的表达式可能违反其他规则。

a + b;
a + b + c;
( a + b ) + c;
a + ( b + c );
a + b - c + d;
( a + b ) - ( c + d );

以下示例展示了多种混合使用运算符的表达式：

/* Compliant - no need to write f ( ( a + b ), c ) */
x = f ( a + b, c );

/* Non-compliant
 * Operands of conditional operator (precedence 2) are:
 *   == precedence 8 needs parentheses
 *   a  precedence 16 does not need parentheses
 *   -  precedence 11 needs parentheses
 */
x = a == b ? a : a - b;

/* Compliant */
x = ( a == b ) ? a : ( a - b );

/* Compliant
 * Operands of << operator (precedence 10) are:
 *   a  precedence 16 does not need parentheses
 *  ( E ) precedence 16 already parenthesized
 */
x = a << ( b + c );

/* Compliant
 * Operands of && operator (precedence 4) are:
 *   a  precedence 16 does not need parentheses
 *   && precedence 4 does not need parentheses
 */
if ( a && b && c )
{
}

/* Compliant
 * Operands of && operator (precedence 4) are:
 *   defined(X) precedence 14 does not need parentheses
 *   (E) precedence 16 already parenthesized
 */
#if defined ( X ) && ( ( X + Y ) > Z )

/* Compliant
 * Operands of && operator (precedence 4) are:
 *   !defined ( X ) precedence 14 does not need parentheses
 *    defined ( Y ) precedence 14 does not need parentheses
 * Operand of ! operator (precedence 14) is:
 *    defined ( X ) precedence 14 does not need parentheses
 */
#if !defined ( X ) && defined ( Y )

注： 本规则不要求用圆括号括住逗号运算符 , 的操作数。Rule 12.3 禁止使用逗号运算符。

x = a, b; /* Compliant - parsed as ( x = a ), b */

原书代码注释中译（按出现顺序）： 前三式依次为：符合，不必改写为 ( a[ i ] )->n；符合，不必写成 *( p++ )；不符合，应根据意图写 sizeof ( x ) + y 或 sizeof ( x + y )。函数调用符合，不必给 a + b 再加一层括号。未加括号的条件运算符（级别 2）不符合：其 ==（8）与减号（11）操作数需加括号，a（16）不需要；改写后符合。移位例符合：a 为 16，( E ) 已有括号、为 16。连续逻辑与的底本注释标为“优先级 4”，并列出 a（16）和 &&（4），都无需括号。第一个 #if 的注释同样将 && 标为 4：defined(X) 为 14，无需括号，(E) 为 16，已有括号。另一个 #if 的注释将 && 标为 4：!defined(X) 和 defined(Y) 都为 14；其中 ! 的操作数 defined(X) 也是 14，无需括号。这两个预处理写法均标为符合。最后的逗号表达式按 ( x = a ), b 解析，注释指符合本条。

源页核对： PDF 113 的注将 Rule 12.3 的措辞写为“禁止”，PDF 114 的 Rule 12.3 主句用 should、类别为 Advisory。两处照录，不将建议级改成必需级。
