Rule 18.4 · 区分下标写法与地址边界

底本定位 PDF／印刷 155–156／147–148。

原文译文

Rule 18.4　不应对指针类型的表达式使用 +、-、+=、-= 运算符。

类别
建议（Advisory）
分析
可判定（Decidable），单一翻译单元（Single Translation Unit）
适用标准
C90、C99

理由

在各种指针算术写法中，宜优先采用数组下标语法 ptr[expr]，因为它通常比直接操纵指针清楚，也较不容易出错。任何显式计算出来的指针值都有可能被用于访问非预期或无效的内存地址。用数组下标也可能出现这种行为，但下标语法可以让人工审查更容易。

C 的指针算术容易让初学者困惑。有人可能把 ptr+1 误解为把 ptr 中保存的地址数值加 1。实际上，新地址取决于指针所指类型的字节大小。基于这种误解而错误地使用 sizeof，可能导致意外行为。

不过，谨慎使用时，某些场合用 ++ 操纵指针可以说更自然。例如，在内存测试中顺序访问各个位置：这时把存储空间视为一组连续位置更方便，而且地址边界可以在编译时确定。

例外

只要满足 Rule 18.2，就允许两个指针相减。

原书示例

void fn1 ( void )
{
  uint8_t  a[ 10 ];
  uint8_t *ptr;
  uint8_t  index = 0U;

  index = index + 1U;     /* Compliant - rule only applies to pointers */

  a[ index ] = 0U;        /* Compliant                                 */
  ptr = &a[ 5 ];          /* Compliant                                 */

  ptr = a;
  ptr++;                  /* Compliant - increment operator not +      */
  *( ptr + 5 ) = 0U;      /* Non-compliant                             */
  ptr[ 5 ] = 0U;          /* Compliant                                 */
}

原书代码注释中译（依次）： （1）合规：本条仅适用于指针。 （2）合规。 （3）合规。 （4）合规：使用的是自增运算符，而不是加法运算符。 （5）不合规。 （6）合规。

void fn2 ( void )
{
  uint8_t array_2_2[ 2 ][ 2 ] = { { 1U, 2U }, { 4U, 5U } };
  uint8_t i = 0U;
  uint8_t j = 0U;
  uint8_t sum = 0U;

  for ( i = 0U; i < 2U; i++ )
  {
    uint8_t *row = array_2_2[ i ];

    for ( j = 0U; j < 2U; j++ )
    {
      sum += row[ j ];   /* Compliant */
    }
  }
}

原书代码注释中译（依次）： 合规。

在下例中，如果 p1 没有指向至少含六个元素的数组，且 p2 没有指向至少含四个元素的数组，还可能违反 Rule 18.1。

void fn3 ( uint8_t *p1, uint8_t p2[ ] )
{
  p1++;                  /* Compliant     */
  p1 = p1 + 5;           /* Non-compliant */
  p1[ 5 ] = 0U;          /* Compliant     */

  p2++;                  /* Compliant     */
  p2 = p2 + 3;           /* Non-compliant */
  p2[ 3 ] = 0U;          /* Compliant     */
}

uint8_t a1[ 16 ];
uint8_t a2[ 16 ];
uint8_t data = 0U;

void fn4 ( void )
{
  fn3 ( a1, a2 );
  fn3 ( &data, &a2[ 4 ] );
}

原书代码注释中译（依次）： （1）合规。 （2）不合规。 （3）合规。 （4）合规。 （5）不合规。 （6）合规。

另见

Rule 18.1、Rule 18.2。

源页核对： PDF 156：原文举出 6 和 4 两个数，用的是“可能违反”，并没有给出充分的安全界限。若从传入位置起依次执行 fn3，最后两次下标写入的位置分别距初始指针 11 和 7 个元素，也就是各需至少 12 和 8 个剩余元素。对 18.4 标为合规的下标写法，并不免于 18.1 的边界检查。
