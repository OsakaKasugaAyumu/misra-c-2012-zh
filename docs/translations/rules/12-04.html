Rule 12.4 · 常量表达式中的无符号回绕

底本定位 规则 PDF／印刷 114–115／106–107。

原文译文

Rule 12.4　常量表达式的求值不应导致无符号整数回绕。

类别
建议（Advisory）
分析
可判定（Decidable），单一翻译单元（Single Translation Unit）
适用标准
C90、C99

进一步说明

只要表达式满足常量表达式的约束，本规则就适用，不论它是否出现在要求使用常量表达式的上下文中。

若表达式不求值，本规则就不适用。例如，它位于逻辑与运算符的右操作数中，而左操作数恒为假。

理由

严格地说，无符号整数表达式不会溢出，而是发生回绕。虽然在运行时使用模算术可能有充分理由，但相比之下，在编译时使用模算术是出于本意的可能性较低。

原书示例

case 标号对应的表达式必须是常量表达式。在求 case 表达式的值时发生无符号回绕，很可能不是有意的。在 int 为 16 位的机器上，下例中 BASE 的任何大于等于 65 024 的值都会造成回绕：

#define BASE 65024u

switch ( x )
{
  case BASE + 0u:
    f ( );
    break;
  case BASE + 1u:
    g ( );
    break;
  case BASE + 512u:   /* Non-compliant - wraps to 0 */
    h ( );
    break;
}

预处理指令 #if 或 #elif 的控制表达式必须是常量表达式。

#if 1u + ( 0u - 10u )   /* Non-compliant as ( 0u - 10u ) wraps */

下例中，表达式 DELAY + WIDTH 的值为 70 000，但在 int 为 16 位的机器上会回绕为 4 464。

#define DELAY 10000u
#define WIDTH 60000u

void fixed_pulse ( void )
{
  uint16_t off_time16 = DELAY + WIDTH;   /* Non-compliant */
}

在下面这个符合本规则的示例中，本规则不适用于表达式 c + 1，因为它访问了一个对象，因而不满足常量表达式的约束：

const uint16_t c = 0xffffu;

void f ( void )
{
  uint16_t y = c + 1u;   /* Compliant */
}

下例的子表达式 ( 0u - 1u ) 会导致无符号整数回绕。初始化 x 时不求该子表达式的值，因此表达式符合本规则。初始化 y 时则可能对它求值，因此表达式不符合本规则。

bool_t b;

void g ( void )
{
  uint16_t x = ( 0u == 0u ) ? 0u : ( 0u - 1u );   /* Compliant     */
  uint16_t y = b ? 0u : ( 0u - 1u );              /* Non-compliant */

}

原书代码注释中译（按出现顺序）： BASE + 512u 不符合：回绕到 0。#if 条件不符合，因为 ( 0u - 10u ) 回绕。用 DELAY + WIDTH 初始化不符合。对象 c 加 1u 的写法符合本条。最后两行初始化分别标为符合、不符合。

源页核对： PDF 115：说明写 c + 1，紧接的原书代码写 c + 1u。两处都照录，不把这两个字面量写成同一类型。此例不适用本条的理由是表达式读取了对象 c，不是后缀 u。
