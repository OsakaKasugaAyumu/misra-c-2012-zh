Rule 14.1 · 辨认浮点循环计数器

原文译文

8.14　控制语句表达式

本节部分规则使用术语“循环计数器”。循环计数器是满足以下条件的对象、数组元素或结构体或联合的成员：

  1. 它具有标量类型；
  2. 对于循环的一次给定执行，它的值在每次迭代中都单调变化；并且
  3. 它参与决定是否退出循环。

注： 第二个条件意味着计数器的值在每次迭代中都必须变化，而且在循环的同一次执行中必须始终向同一方向变化。不过，在该循环的不同次执行中，变化方向可以不同，例如有时逆序读取数组元素，有时顺序读取。

按此定义，循环不一定恰好只有一个计数器：既可能没有计数器，也可能有多个。关于 for 循环计数器的进一步限制，见 Rule 14.2。

以下代码片段展示了若干循环及其相应的计数器。

在这个循环中，i 是循环计数器，因为它具有标量类型，单调变化（递增），而且参与循环终止条件的判断。

for ( uint16_t i = 0; a[ i ] < 10; ++i )
{
}

下面的循环没有循环计数器。对象 count 具有标量类型，且单调变化，但不参与终止条件的判断。

extern volatile bool_t b;
uint16_t  count = 0;

while ( b )
{
  count = count + 1U;
}

在下面的代码中，i 和 sum 均为标量，且都单调变化（分别递减和递增）。不过，sum 不参与决定是否退出循环，因此不是循环计数器。

uint16_t sum = 0;

for ( uint16_t i = 10U; i != 0U; --i )
{
  sum += i;
}

在下面的循环中，p 是循环计数器。它不参与循环控制表达式，但参与决定是否通过 break 语句退出循环。

extern volatile bool_t b;

extern char *p;

do
{
  if ( *p == '\0' )
  {
    break;
  }

  ++p;
} while ( b );

下例的循环计数器是 p->count。

struct s
{
  uint16_t count;
  uint16_t a[ 10 ];
};

extern struct s *p;

for ( p->count = 0U; p->count < 10U; ++( p->count ) )
{
  p->a[ p->count ] = 0U;
}

Rule 14.1　循环计数器不得具有本质浮点类型。

类别
必需（Required）
分析
不可判定（Undecidable），系统（System）
适用标准
C90、C99

理由

使用浮点循环计数器时，舍入误差的累积可能导致实际迭代次数与预期次数不一致。如果循环步长不是浮点基数的幂，因而被舍入为一个可表示的值，就可能出现这种情况。

即使使用浮点计数器的循环在一种实现上看似工作正常，它在另一种实现上的迭代次数也可能不同。

原书示例

在下面这个不符合本规则的示例中，循环结束时 counter 的值不大可能是 1 000。

uint32_t counter = 0u;

for ( float32_t f = 0.0f; f < 1.0f; f += 0.001f )
{
  ++counter;
}

下面这个符合本规则的示例使用整数循环计数器，保证迭代 1 000 次，并在循环体中用计数器生成 f。

float32_t f;

for ( uint32_t counter = 0u; counter < 1000u; ++counter )
{
  f = ( float32_t ) counter * 0.001f;
}

下面的 while 循环不符合本规则，因为 f 用作循环计数器。

float32_t f = 0.0f;

while ( f < 1.0f )
{
  f += 0.001f;
}

下面的 while 循环符合本规则，因为 f 没有用作循环计数器。

float32_t f;
uint32_t  u32a;

f = read_float32 ( );

do
{
  u32a = read_u32 ( );
  /* f does not change in the loop so cannot be a loop counter */
} while ( ( ( float32_t ) u32a - f ) > 10.0f );

Rule 14.2。

原书代码注释中译（按出现顺序）： 最后一个示例中，f 在循环内不变化，因此不可能是循环计数器。
