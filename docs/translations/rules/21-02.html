Rule 21.2 · 辨认声明来自应用还是标准头

底本定位 PDF／印刷 174–175／166–167。

原文译文

Rule 21.2　不得声明保留标识符或保留宏名。

C90 [未定义 57、58、64、71]；C99 [未定义 93、100、101、104、108、116、118、130]

类别
必需（Required）
分析
可判定（Decidable），单一翻译单元（Single Translation Unit）
适用标准
C90、C99

进一步说明

相关标识符和宏名的说明见 Rule 21.1 的“进一步说明”。

理由

实现可以依赖保留标识符按 C 标准所述方式行事，也可以对它们作特殊处理。如果这些保留标识符被挪作他用，程序可能表现出未定义行为。

原书示例

在下列不合规示例中，函数 memcpy 是显式声明的。声明该函数的合规方式是包含 <string.h>。

/*
 * Include <stddef.h> to define size_t
 */
#include <stddef.h>
extern void *memcpy ( void *restrict s1, const void *restrict s2, size_t n );

原书代码注释中译（依次）： （1）包含 <stddef.h> 以定义 size_t。

除库函数本身之外，实现还可以为每个标准库函数提供一个函数式宏定义。编译器开发者常利用这一特性，在库函数调用处生成高效的内联操作。借助函数式宏，可以把库函数调用替换为对某个保留函数的调用；编译器在代码生成阶段识别后者，再用内联操作替代它。例如，<math.h> 中声明 sqrt 的片段可能采用如下函数式宏，由此生成一次对 _BUILTIN_sqrt 的调用；在支持该指令的处理器上，这次调用会被替换成一条内联的 SQRT 指令：

extern double sqrt ( double x );

#define sqrt( x ) ( _BUILTIN_sqrt ( x ) )

以下不合规代码可能干扰编译器处理 sqrt 的内建机制，因而产生未定义行为：

#define _BUILTIN_sqrt( x ) ( x )            /* Non-compliant           */
#include <math.h>

float64_t x = sqrt ( ( float64_t ) 2.0 );   /* sqrt may not behave as
                                             * defined in The Standard */

原书代码注释中译（依次）： （1）不合规。 （2）sqrt 的行为可能不再符合 C 标准的规定。

源页核对： PDF 174–175：_BUILTIN_sqrt 是原书假设的实现内部名字，不是对所有编译器的描述；跨页的干扰示例仍属本条。
