Rule 11.3 · 不同对象类型之间的指针强转

底本定位 规则 PDF／印刷 104–105／96–97。

原文译文

Rule 11.3　不得在指向某一对象类型的指针与指向不同对象类型的指针之间进行强制转换。

C90 [未定义 20]；C99 [未定义 22、34]

类别
必需（Required）
分析
可判定（Decidable），单一翻译单元（Single Translation Unit）
适用标准
C90、C99

进一步说明

本规则针对指针所指向的类型，判断时取该类型的非限定形式。

理由

将指向对象的指针强制转换为指向不同对象的指针，可能产生未正确对齐的指针，导致未定义行为。

即使已知转换所得指针正确对齐，用它访问对象仍可能引发未定义行为。例如，通过 short 类型访问 int 对象，即使 int 和 short 具有相同的表示和对齐要求，行为仍是未定义的。详见 C90 §6.3、C99 §6.5 第 7 段。

例外

允许把指向对象类型的指针转换为指向 char、signed char 或 unsigned char 这三种对象类型之一的指针。C 标准保证可用指向这些类型的指针逐字节访问一个对象。

原书示例

uint8_t  *p1;
uint32_t *p2;

/* Non-compliant - possible incompatible alignment */
p2 = ( uint32_t * ) p1;

extern uint32_t read_value ( void );
extern void print ( uint32_t n );

void f ( void )
{
  uint32_t  u    = read_value ( );
  uint16_t *hi_p = ( uint16_t * ) &u;   /* Non-compliant even though
                                         * probably correctly aligned   */

  *hi_p = 0;     /* Attempt to clear high 16-bits on big-endian machine */
  print ( u );   /* Line above may appear not to have been performed    */
}

下例符合本规则，因为本规则针对的是非限定的指针类型。它不禁止给对象类型增加类型限定符。

const short *p;
const volatile short *q;

q = ( const volatile short * ) p;   /* Compliant */

下例不符合本规则，因为非限定的指针类型不同，分别为“指向经 const 限定的 int 的指针”和“指向 int 的指针”。

int * const * pcpi;
const int * const * pcpci;

pcpci = ( const int * const * ) pcpi;

另见

Rule 11.4、Rule 11.5、Rule 11.8。

原书代码注释中译（按出现顺序）： p2 的转换不符合：对齐要求可能不兼容。取得 hi_p 的转换即使很可能正确对齐也不符合。写入的意图是在大端机器上清除高 16 位；打印时，前一行看起来可能像是没有执行。向 q 赋值的限定符转换符合本规则。
