原文译文

§8.19　重叠存储

Rule 19.1　不得将一个对象赋值或复制给与其存储区域重叠的对象。

C90 [未定义 34、55]；C99 [未定义 51、94]

类别
强制（Mandatory）
分析
不可判定（Undecidable），系统（System）
适用标准
C90、C99

理由

当创建的两个对象在内存中有所重叠，而又把一个赋值或复制给另一个时，行为就未定义。

例外

以下两种情形的行为有明确定义，因此允许：

  1. 在存储区域完全重合且类型兼容的两个对象之间进行赋值（判断类型兼容性时忽略类型限定符）。
  2. 使用标准库函数 memmove 在存储区域部分或完全重合的对象之间复制。

原书示例

因为使用了联合体，本例还违反 Rule 19.2。

void fn ( void )
{
  union
  {
    int16_t i;
    int32_t j;
  } a = { 0 }, b = { 1 };

  a.j = a.i;                /* Non-compliant           */
  a = b;                    /* Compliant - exception 1 */
}

原书代码注释中译（依次）： （1）不合规。 （2）合规：例外 1。

#include <string.h>

int16_t a[ 20 ];

void f ( void )
{
  memcpy ( &a[ 5 ], &a[ 4 ], 2u * sizeof ( a[ 0 ] ) ); /* Non-compliant */
}

void g ( void )
{
  int16_t  *p = &a[ 0 ];
  int16_t  *q = &a[ 0 ];

  *p = *q;   /* Compliant - exception 1 */
}

原书代码注释中译（依次）： （1）不合规。 （2）合规：例外 1。

另见

Rule 19.2。

源页核对： PDF 161：原书给 a = b 标注“合规：例外 1”，但所示声明中的 a、b 是两个不同的联合体对象，未显示它们完全重叠。正文和代码注释均保留；第 162 页 *p = *q 才明确显示了与例外 1 相符的同址赋值。
