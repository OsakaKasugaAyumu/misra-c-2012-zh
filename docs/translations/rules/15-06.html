Rule 15.6 · 用复合语句界定受控语句体

底本定位 PDF／印刷 135–136／127–128。

原文译文

Rule 15.6　迭代语句或选择语句的语句体必须是复合语句。

[Koenig 24]

类别
必需（Required）
分析
可判定（Decidable），单一翻译单元（Single Translation Unit）
适用标准
C90、C99

进一步说明

迭代语句（while、do … while 或 for）以及选择语句（if、else、switch）的语句体必须是复合语句。

理由

开发者可能因为缩进而误以为一连串语句都属于迭代或选择语句的语句体。尤其危险的是在控制表达式后误加分号，导致实际受控的是空语句。使用复合语句可以明确哪些语句实际属于语句体。

此外，缩进还可能使开发者把 else 与错误的 if 配对。

例外

紧接在 else 后的 if 语句不必包在复合语句内。

原书示例

复合语句及其两侧花括号的排版属于风格问题，不在本文档的规定范围内；下例的风格不是强制要求。

维护下列代码时：

while ( data_available )
  process_data ( );             /* Non-compliant */

原书代码注释中译（依次）： 不合规。

可能无意中把它改成：

while ( data_available )
  process_data ( );             /* Non-compliant */
  service_watchdog ( );

原书代码注释中译（依次）： 不合规。

这里原本应当把 service_watchdog() 加入循环体。使用复合语句能显著降低这类失误的可能性。

下例看起来像是 action_2() 位于第一个 if 的 else 分支：

if ( flag_1 )
  if ( flag_2 )                 /* Non-compliant */
    action_1 ( );               /* Non-compliant */
else
  action_2 ( );                 /* Non-compliant */

原书代码注释中译（依次）： （1）不合规。 （2）不合规。 （3）不合规。

实际行为却是：

if ( flag_1 )
{
  if ( flag_2 )
  {
    action_1 ( );
  }
  else
  {
    action_2 ( );
  }
}

使用复合语句可以明确 if 与 else 的配对关系。

上述例外允许使用 else if，如下所示：

if ( flag_1 )
{
  action_1 ( );
}
else if ( flag_2 )              /* Compliant by exception */
{
  action_2 ( );
}
else
{
  ;
}

原书代码注释中译（依次）： 依据例外，合规。

下例说明多余的分号如何导致错误：

while ( flag );                 /* Non-compliant */
{
  flag = fn ( );
}

原书代码注释中译（依次）： 不合规。

下例是编写空循环体的合规方式：

while ( !data_available )
{
}
