Rule 8.13 · 指针所指类型的 const 限定

底本定位 §8.8 · PDF／印刷 81–82／73–74

原文译文

Rule 8.13　凡有可能，指针都应当指向带 const 限定的类型。

类别
建议（Advisory）
分析
不可判定（Undecidable），系统（System）
适用标准
C90、C99

进一步说明

指针应指向带 const 限定的类型，除非满足下述任一条件：

  • 该指针用于修改对象；或
  • 该指针通过下列任一方式被复制到另一指针，而后者指向的类型没有 const 限定：
    • 赋值；或
    • 内存移动或复制函数。

为简明起见，本规则以指针及其所指类型来表述。但它也同样适用于数组及其元素类型。数组元素的类型应有 const 限定，除非满足下述任一条件：

  • 数组中有元素被修改；或
  • 通过上述方式将它复制到指向非 const 限定类型的指针。

理由

本规则通过确保指针不被无意用于修改对象来鼓励良好实践。在概念上，这相当于先将：

  • 所有数组声明为其元素具有 const 限定类型；并将
  • 所有指针声明为指向 const 限定类型；

然后，仅在为符合语言标准的约束而有必要时，才移除 const 限定。

原书示例

在下面不符合本规则的示例中，p 没有用于修改对象，但它所指的类型并没有 const 限定。

uint16_t f ( uint16_t *p )
{
  return *p;
}

如果函数按下列形式定义，这段代码就符合本规则：

uint16_t g ( const uint16_t *p )

下例违反了一项约束，因为它试图使用一个有 const 限定的指针修改对象。

void h ( const uint16_t *p )
{
  *p = 0;
}

在下例中，指针 s 自身有 const 限定，但它指向的类型没有。由于 s 未用于修改对象，这不符合本规则。

#include <string.h>

char last_char ( char * const s )
{
  return s[ strlen ( s ) - 1u ];
}

如果函数按下列形式定义，这段代码就符合本规则：

char last_char ( const char * const s )

在这个不符合本规则的示例中，数组 a 的元素均未修改，但元素类型没有 const 限定。

uint16_t first ( uint16_t a[ 5 ] )
{
  return a[ 0 ];
}

如果函数按下列形式定义，这段代码就符合本规则：

uint16_t first ( const uint16_t a[ 5 ] )

源页核对： PDF 82 的理由后示例把指针称为“有 const 限定的指针”；h 的代码写的是 const uint16_t *p，即限定所指类型，而不是指针对象。本页保留原句及原代码，勿据此混同二者。
