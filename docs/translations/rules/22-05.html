Rule 22.5 · 区分复制句柄和复制 FILE 对象

底本定位 PDF／印刷 184–185／176–177。

原文译文

Rule 22.5　不得对指向 FILE 对象的指针进行解引用。

类别
强制（Mandatory）
分析
不可判定（Undecidable），系统（System）
适用标准
C90、C99

进一步说明

不得直接或间接地对指向 FILE 对象的指针进行解引用（间接方式例如调用 memcpy 或 memcmp）。

理由

C 标准（C90 第 7.9.3(6) 节、C99 第 7.19.3(6) 节）指出，用来控制一个流的 FILE 对象，其地址可能有特殊意义，而该对象的副本不一定具有相同的行为。本规则确保不能制作这种副本。

禁止直接操纵 FILE 对象，因为这可能与它作为流指示器的用途不相容。

原书示例

#include <stdio.h>

FILE *pf1;
FILE *pf2;
FILE  f3;

pf2 = pf1;      /* Compliant     */
 f3 = *pf2;     /* Non-compliant */

原书代码注释中译（依次）： （1）合规。 （2）不合规。

下例假定 FILE * 指定一个具有名为 pos 的成员的完整类型：

pf1->pos = 0;   /* Non-compliant */

原书代码注释中译（依次）： （1）不合规。

另见

Rule 21.6。

源页核对： PDF 185：原书写作“FILE * 指定一个具有 pos 成员的完整类型”。示例用 -> 访问的是指针所指对象的成员；这是原书的假设，不是 FILE 的可移植接口。
