Rule 10.7 · 复合操作数与另一侧的宽度

底本定位 规则 PDF／印刷 99–100／91–92。

原文译文

Rule 10.7　如果实施通常算术转换的运算符以复合表达式为一个操作数，则另一个操作数的本质类型不得比该复合表达式的本质类型更宽。

类别
必需（Required）
分析
可判定（Decidable），单一翻译单元（Single Translation Unit）
适用标准
C90、C99

理由

理由见关于复合运算符与复合表达式的导言（§8.10.3）。

限制对复合表达式的隐式转换，意味着表达式内连续的算术运算必须在完全相同的本质类型中进行。这减少了开发者产生混淆的可能性。

注： 这并不意味着一个表达式中的所有操作数都具有相同的本质类型。

表达式 u32a + u16b + u16c 符合本规则，因为从本质类型看，两次加法都在 uint32_t 类型中进行。此时只有非复合表达式发生隐式转换。

表达式 (u16a + u16b) + u32c 不符合本规则，因为从本质类型看，左边的加法在 uint16_t 类型中进行，右边的加法在 uint32_t 类型中进行，需要把复合表达式 u16a + u16b 隐式转换为 uint32_t。

原书示例

以下写法符合本规则：

  u32a * u16a + u16b                    /* No composite conversion       */
( u32a * u16a ) + u16b                  /* No composite conversion       */
  u32a * ( ( uint32_t ) u16a + u16b )   /* Both operands of * have
                                         * same essential type           */
 u32a += ( u32b + u16b )                /* No composite conversion       */

以下写法不符合本规则：

  u32a * ( u16a + u16b )   /* Implicit conversion of ( u16a + u16b )     */
 u32a += ( u16a + u16b )   /* Implicit conversion of ( u16a + u16b )     */

另见

Rule 10.4、Rule 10.6、§8.10.3。

原书代码注释中译（按出现顺序）： 前三式分别为：没有复合表达式转换、没有复合表达式转换、乘号两侧本质类型相同。第四式没有复合表达式转换。两项反例都隐式转换了 u16a + u16b。
