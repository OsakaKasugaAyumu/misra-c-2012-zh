Rule 5.3 · 内层声明不得遮蔽外层标识符

底本定位 §8.5 · PDF 58–59／印刷 50–51

原文译文

Rule 5.3　在内层作用域声明的标识符不得遮蔽在外层作用域声明的标识符。

类别
必需（Required）
分析
可判定（Decidable），单一翻译单元（Single Translation Unit）
适用标准
C90、C99

进一步说明

在内层作用域声明的标识符必须能与在外层作用域声明的任何标识符区分开。

何谓“可区分”，取决于实现以及所使用的 C 语言版本：

  • C90 的最低要求是前 31 个字符有效；
  • C99 的最低要求是前 63 个字符有效，每个通用字符或扩展源字符按一个字符计。

理由

如果内层声明的标识符不能与外层作用域中已经存在的标识符区分开，最内层的声明就会“遮蔽”外层的声明。这可能使开发者产生混淆。

注： 在一个名字空间中声明的标识符不会遮蔽在另一个名字空间中声明的标识符。

“外层作用域”和“内层作用域”的含义如下：

  • 具有文件作用域的标识符可视为具有最外层的作用域；
  • 具有块作用域的标识符，其作用域更靠内；
  • 逐层嵌套的块会引入更内层的作用域。

原书示例

void fn1 ( void )
{
  int16_t i;       /* Declare an object "i"                              */

  {
    int16_t i;     /* Non-compliant - hides previous "i"                 */

    i = 3;         /* Could be confusing as to which "i" this refers     */
  }
}

struct astruct
{
  int16_t m;
};

extern void g ( struct astruct *p );

int16_t xyz = 0;                       /* Declare an object "xyz"        */

void fn2 ( struct astruct xyz )        /* Non-compliant - outer "xyz" is
                                        * now hidden by parameter name   */
{
  g ( &xyz );
}

uint16_t speed;

void fn3 ( void )
{
  typedef float32_t speed;   /* Non-compliant - type hides object        */
}

另见

Rule 5.2、Rule 5.8。

原书代码注释中译（按出现顺序）　先声明对象 i，内层又声明 i，遮蔽先前的 i，赋值究竟指哪个 i 容易混淆。先声明对象 xyz，随后形参名遮蔽外层 xyz，不符合。最后的类型名 speed 遮蔽对象，也不符合。
