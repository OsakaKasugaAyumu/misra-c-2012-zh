8.10　本质类型模型

8.10.1　理由

本节各条规则共同定义了本质类型模型，并对 C 的类型系统施加限制，目的是：

  1. 支持更强的类型检查；
  2. 为制定控制隐式和显式类型转换的规则提供合理依据；
  3. 提倡可移植的编码做法；
  4. 处理 ISO C 中某些反常的类型转换现象。

对于 ISO C 视为算术类型的对象和表达式，本质类型模型分别赋予其本质类型。例如，int 与 char 相加，结果的本质类型是字符，而不是整型提升实际产生的 int 类型。

附录 C 完整阐述了采用本质类型模型的理由；附录 D 全面定义了如何确定任一算术表达式的本质类型。

8.10.2　本质类型

对象或表达式的本质类型由其本质类型类别和大小共同确定。表达式的本质类型类别反映其底层行为，可以是：

  • 本质布尔型；
  • 本质字符型；
  • 本质枚举型；
  • 本质有符号型；
  • 本质无符号型；
  • 本质浮点型。

注： 每种枚举类型都是一种独有的本质枚举类型，以 enum<i> 标识。这使不同枚举类型能够作为互不相同的类型处理，从而支持更强的类型检查。一个例外是 C90 中用枚举类型定义布尔值的情形：这样的类型被视为本质布尔型。另一个例外是使用附录 D 定义的匿名枚举。匿名枚举是定义一组相关整型常量的方法，被视为具有本质有符号类型。

比较同一类型类别中的两个类型时，用“较宽”和“较窄”描述两者按字节计的相对大小。两种不同类型在某些实现中的大小相同。

就本规则而言，++ 和 -- 的行为分别与二元 + 和 - 相同。对于表达式中可以组合使用哪些本质类型，另有其他规则作进一步限制。

理由

  1. 将本质浮点型表达式用作这些操作数违反约束。
  2. 当操作数被解释为布尔值时，始终应使用本质布尔型表达式。
  3. 当操作数被解释为数值时，不应使用本质布尔型操作数。
  4. 当操作数被解释为数值时，不应使用本质字符型操作数。字符数据的数值由实现定义。
  5. 算术运算不应使用本质枚举型操作数，因为枚举对象使用的整数类型由实现定义。因此，涉及枚举对象的运算可能得到类型出乎预期的结果。注意：匿名枚举的枚举常量具有本质有符号类型。
  6. 移位和按位运算只应对本质无符号型操作数进行。对本质有符号类型进行这些运算所得到的数值由实现定义。
  7. 移位运算符的右操作数应具有本质无符号类型，以避免移位量为负而引发未定义行为。
  8. 一元负号运算符不应使用本质无符号型操作数，因为结果的符号性取决于实现中 int 的大小。

例外

本质有符号型的非负整型常量表达式可用作移位运算符的右操作数。
