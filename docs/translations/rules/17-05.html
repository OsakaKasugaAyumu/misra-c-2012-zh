Rule 17.5 · 核对数组实参的剩余元素数

底本定位 PDF／印刷 147–148／139–140。

原文译文

Rule 17.5　对于声明为数组类型的形参，对应的函数实参必须具有适当数量的元素。

类别
建议（Advisory）
分析
不可判定（Undecidable），系统（System）
适用标准
C90、C99

进一步说明

如果形参声明为指定长度的数组，则在每次函数调用中，对应实参所指向的对象都应至少能提供与该数组一样多的元素。

理由

用数组声明符而不是指针声明函数形参，能更清楚地规定函数接口。这样可以明示函数所期望的最少元素数，而用指针就无法表明这一点。

如果函数形参的数组声明符没有指定长度，则视为表示该函数能处理任意长度的数组。在这种情况下，预期会通过其他方式传达数组长度，例如将长度作为另一个形参传入，或用哨兵值标记数组末尾。

建议使用数组界限，以便在函数体内实施越界检查，并在传参时进行额外检查。对于指定了长度的形参，C 语言允许传入长度不正确的数组，这可能导致意外行为。

原书示例

/*
 * Intent is that function does not access outside the range
 * array1[ 0 ] .. array1[ 3 ]
 */
void fn1 ( int32_t array1[ 4 ] );

/* Intent is that function handles arrays of any size           */
void fn2 ( int32_t array2[ ] );

void fn ( int32_t *ptr )
{
  int32_t arr3[ 3 ] = { 1, 2, 3 };
  int32_t arr4[ 4 ] = { 0, 1, 2, 3 };

  /* Compliant - size of array matches the prototype            */
  fn1 ( arr4 );

  /* Non-compliant - size of array does not match prototype     */
  fn1 ( arr3 );

  /* Compliant only if ptr points to at least 4 elements        */
  fn1 ( ptr );

  /* Compliant                                                  */
  fn2 ( arr4 );

  /* Compliant                                                  */
  fn2 ( ptr );
}

原书代码注释中译（依次）： （1）意图：函数不访问 array1[0] 至 array1[3] 以外的位置。 （2）意图：函数处理任意大小的数组。 （3）合规：数组大小符合原型。 （4）不合规：数组大小不符合原型。 （5）只有在 ptr 指向至少四个元素时才合规。 （6）合规。 （7）合规。
