Rule 12.2 · 移位量的上下界

底本定位 规则 PDF／印刷 113–114／105–106。

原文译文

Rule 12.2　移位运算符的右操作数必须在零至左操作数本质类型的位宽减一的范围内。

C90 [未定义 32]；C99 [未定义 48]

类别
必需（Required）
分析
不可判定（Undecidable），系统（System）
适用标准
C90、C99

理由

若右操作数为负，或大于等于左操作数的宽度，则行为未定义。

例如，如果左移或右移运算符的左操作数是 16 位整数，就必须确保移位量仅在 0 至 15 的范围内。

关于本质类型及移位操作数本质类型的限制，见 §8.10。

有多种方法可以确保遵守本规则。最简单的是让右操作数为常量（从而可以静态检查其值）。使用无符号整数类型可以保证操作数非负，这样只需检查上限（运行期间动态检查，或通过审查检查）。否则必须同时检查上下限。

原书示例

u8a = u8a << 7;                 /* Compliant     */
u8a = u8a << 8;                 /* Non-compliant */
u16a = ( uint16_t ) u8a << 9;   /* Compliant     */

为便于理解以下示例，应注意 1u 的本质类型是本质无符号 char，而 1UL 的本质类型是本质无符号 long。

1u << 10u;                      /* Non-compliant */
( uint16_t ) 1u << 10u;         /* Compliant     */
1UL << 10u;                     /* Compliant     */

原书代码注释中译（按出现顺序）： 8 位操作数移 7 位符合，移 8 位不符合；先转成 uint16_t 再移 9 位符合。1u 移 10 位不符合；先转为 uint16_t 或改用 1UL 的两式符合。

源页核对： PDF 113–114：规则以左操作数的本质位宽为界。底本理由对未定义行为的说明，不等于所有超出本质位宽的移位在 ISO C 中都未定义；C 的判断要另看整型提升后的宽度。
