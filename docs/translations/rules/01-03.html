Rule 1.3 · 未定义行为与关键的未指定行为

底本定位 §8.1 · PDF 46–47／印刷 38–39

原文译文

Rule 1.3　不得出现未定义行为或关键的未指定行为。

类别
必需（Required）
分析
不可判定（Undecidable），系统（System）
适用标准
C90、C99

进一步说明

某些未定义行为和未指定行为已有专门规则处理。本规则用于防止其余所有未定义行为和关键的未指定行为。附录 H 列出了未定义行为以及被认为是关键的未指定行为。

理由

任何引发未定义行为或未指定行为的程序都可能不按预期运行。在许多情况下，这会使程序失去可移植性，但也可能产生更严重的后果。例如，未定义行为可能影响某次计算的结果。如果软件的正确运行依赖这次计算，系统安全就可能受到损害。如果未定义行为只在罕见的情况下显现，问题就尤其难以发现。

许多 MISRA C 准则的目的正是避免某些未定义行为和未指定行为。例如，同时遵守 Rule 11.4、Rule 11.8 和 Rule 19.2，就能保证在 C 中不可能为一个以 const 限定类型声明的对象创建一个指向非 const 限定类型的指针。这避免了 C90 [Undefined 39] 和 C99 [Undefined 61]。不过，另一些行为没有专门准则涵盖，例如，原因可能是：

  • 实际遇到该行为的可能性很低；
  • 除了显而易见地指出应避免该行为外，无法给出切实可行的指导。

MISRA C 指南没有为每一种未定义行为和关键的未指定行为各设一条准则，而是直接处理其中被认为最重要、且在实践中最可能出现的行为。没有专门准则的那些行为全部由本规则统一涵盖。附录 H 列出全部未定义行为和关键的未指定行为，以及防止它们发生的 MISRA C 准则。因此，附录 H 表明哪些行为应由本规则防止，哪些由其他规则涵盖。

注： 对于标准所列的某些未定义行为和未指定行为，一些实现可能给出明确定义的行为。如果程序依赖这类明确定义的行为，包括通过语言扩展产生依赖，就必须针对所涉及的行为办理对此规则的偏离。
