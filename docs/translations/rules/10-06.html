Rule 10.6 · 复合表达式的赋值目标

底本定位 规则 PDF／印刷 99／91。上接 PDF 98（印刷 90）的 §8.10.3。

原文译文

8.10.3　复合运算符与复合表达式

通过限制可对非平凡表达式施加的隐式和显式转换，可以避免附录 C 提到的某些问题。这些问题包括：

  • 不清楚整型表达式以哪种类型求值：这取决于各操作数经过整型提升后的类型。算术运算结果的类型取决于实现中 int 的大小；
  • 程序员常误以为，计算采用哪种类型会受接收结果的赋值目标类型或强制转换目标类型影响。这种错误预期可能导致非预期结果。

除了前面的规则，本质类型模型还进一步限制以复合表达式为操作数的表达式。复合表达式的定义如下。

本文档将下列运算符定义为复合运算符：

  • 乘法类（*、/、%）；
  • 加法类（二元 +、二元 -）；
  • 按位（&、|、^）；
  • 移位（<<、>>）；
  • 条件（?:），前提是第二或第三操作数中至少有一个是复合表达式。

复合赋值等价于将其对应复合运算符的结果赋回。本文档将复合表达式定义为：直接由复合运算符产生的非常量表达式。

注：

  • 复合赋值运算符的结果不是复合表达式；
  • 加上括号的复合表达式仍是复合表达式；
  • 常量表达式不是复合表达式。

Rule 10.6　不得将复合表达式的值赋给具有较宽本质类型的对象。

类别
必需（Required）
分析
可判定（Decidable），单一翻译单元（Single Translation Unit）

C90、C99

进一步说明

本规则涵盖 Rule 10.3 所述的赋值操作。

理由

理由见关于复合运算符与复合表达式的导言（§8.10.3）。

原书示例

以下写法符合本规则：

u16c = u16a + u16b;               /* Same essential type                */
u32a = ( uint32_t ) u16a + u16b;  /* Cast causes addition in uint32_t   */

以下写法不符合本规则：

u32a = u16a + u16b;               /* Implicit conversion on assignment  */
use_uint32 ( u16a + u16b );       /* Implicit conversion of fn argument */

另见

Rule 10.3、Rule 10.7、§8.10.3。

原书代码注释中译（按出现顺序）： 两个符合项分别具有相同本质类型、通过强转使加法在 uint32_t 中进行。两项反例分别在赋值、传递函数实参时发生隐式转换。
