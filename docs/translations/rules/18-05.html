Rule 18.5 · 展开 typedef 并按连续层级计数

底本定位 PDF／印刷 156–157／148–149。

原文译文

Rule 18.5　声明中指针的嵌套不应超过两级。

类别
建议（Advisory）
分析
可判定（Decidable），单一翻译单元（Single Translation Unit）
适用标准
C90、C99

进一步说明

连续施加在同一类型上的指针声明符不应超过两个。声明中出现的任何 typedef 名，都要当作用它所代表的类型替换之后再作判断。

理由

超过两级的指针嵌套可能严重妨碍对代码行为的理解，因此应当避免。

原书示例

typedef int8_t * INTPTR;

void function ( int8_t ** arrPar[ ] )  /* Non-compliant */
{
   int8_t **  obj2;                    /* Compliant     */
   int8_t *** obj3;                    /* Non-compliant */
   INTPTR *   obj4;                    /* Compliant     */
   INTPTR *   const * const obj5;      /* Non-compliant */
   int8_t **  arr[ 10 ];               /* Compliant     */
   int8_t **  ( *parr )[ 10 ];         /* Compliant     */
   int8_t *   ( **pparr )[ 10 ];       /* Compliant     */
}

struct s
{
   int8_t *   s1;                      /* Compliant     */
   int8_t **  s2;                      /* Compliant     */
   int8_t *** s3;                      /* Non-compliant */
};

struct s *   ps1;                      /* Compliant     */
struct s **  ps2;                      /* Compliant     */
struct s *** ps3;                      /* Non-compliant */

int8_t **  (   *pfunc1 )( void );      /* Compliant     */
int8_t **  (  **pfunc2 )( void );      /* Compliant     */
int8_t **  ( ***pfunc3 )( void );      /* Non-compliant */
int8_t *** (  **pfunc4 )( void );      /* Non-compliant */

原书代码注释中译（依次）： （1）不合规。 （2）合规。 （3）不合规。 （4）合规。 （5）不合规。 （6）合规。 （7）合规。 （8）合规。 （9）合规。 （10）合规。 （11）不合规。 （12）合规。 （13）合规。 （14）不合规。 （15）合规。 （16）合规。 （17）不合规。 （18）不合规。

注：

  • arrPar 的类型是指向“指向 int8_t 的指针的指针”的指针，因为声明为数组类型的形参会转换为指向数组首元素的指针。因此这里连续有三级，不合规。
  • arr 的类型是数组，元素是指向 int8_t 的二级指针；合规。
  • parr 是指向数组的指针，该数组的元素是指向 int8_t 的二级指针；合规。
  • pparr 是指向数组的二级指针，该数组的元素是指向 int8_t 的指针；合规。
