Rule 20.13 · 检查被排除分支中的指令拼写

底本定位 PDF／印刷 171–172／163–164。

原文译文

Rule 20.13　某行的第一个记号若为 #，该行就必须是一条有效的预处理指令。

类别
必需（Required）
分析
可判定（Decidable），单一翻译单元（Single Translation Unit）
适用标准
C90、C99

进一步说明

# 和预处理记号之间允许有空白。

理由

预处理指令可用于按条件排除源代码，直到遇到相应的 #else、#elif 或 #endif 指令。在被排除的源代码中，如果有格式不正确或无效的预处理指令，编译器可能发现不了，从而排除比原意更多的代码。

即使指令位于被排除的代码块内，也要求所有预处理指令的语法都有效，这样便能防止上述情况发生。

原书示例

在下例中，如果 AAA 已定义，#ifndef 与 #endif 指令之间的代码可能全部被排除。开发者本想把 AAA 赋给 x，却把 #else 指令输错了，而编译器没有诊断出这个错误。

#define AAA 2

int32_t foo ( void )
{
  int32_t x = 0;

#ifndef AAA
  x = 1;
#else1        /* Non-compliant */
  x = AAA;
#endif

  return x;
}

原书代码注释中译（依次）： （1）不合规。

下例合规，因为注释中的文本 #start 不是记号。

/*
#start is not a token in a comment
 */

原书代码注释中译（依次）： （1）注释中的 #start 不是记号。
