Rule 8.3 · 各次声明中的名称和类型限定符

底本定位 §8.8 · PDF／印刷 74–75／66–67

原文译文

Rule 8.3　同一对象或函数的所有声明必须使用相同的名称和类型限定符。

C90 [未定义 10]，C99 [未定义 14]，[Koenig 59–62]

类别
必需（Required）
分析
可判定（Decidable），系统（System）
适用标准
C90、C99

进一步说明

存储类说明符不在本规则的范围内。

理由

在同一对象或函数的各次声明中一致地使用类型和限定符，有助于加强类型约束。

在函数原型中指定形参名，使得可以对照函数的声明检查其定义的接口是否一致。

例外

同一基本类型的兼容写法可以互换。例如，int、signed 和 signed int 三者等价。

原书示例

extern void f ( signed int );
       void f (        int );    /* Compliant     - Exception       */
extern void g ( int * const );
       void g ( int *       );   /* Non-compliant - type qualifiers */

注： 以上各项均不符合 Dir 4.6。

extern int16_t func ( int16_t num, int16_t den );

/* Non-compliant - parameter names do not match */
int16_t func ( int16_t den, int16_t num )
{
  return num / den;
}

在下例中，area 的定义对形参 h 使用的类型名与声明中使用的不同。即使 width_t 和 height_t 是相同的基本类型，这种写法仍不符合本规则。

typedef uint16_t width_t;
typedef uint16_t height_t;
typedef uint32_t area_t;

extern area_t area ( width_t w, height_t h );

area_t area ( width_t w, width_t h )
{
  return ( area_t ) w * h;
}

本规则不要求函数指针声明使用与函数声明相同的名称。所以下例是符合的。

extern void f1 ( int16_t x );
extern void f2 ( int16_t y );

void f ( bool_t b )
{
  void ( *fp1 ) ( int16_t z ) = b ? f1 : f2;
}

另见

Rule 8.4

原书代码注释中译（按出现顺序）： f 的两种基本类型写法按例外符合；g 的类型限定符不同，不符合。func 的形参名与对应位置不一致，不符合。
