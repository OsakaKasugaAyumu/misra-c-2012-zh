Rule 5.7 · 标记名的唯一性

底本定位 §8.5 · PDF 63–64／印刷 55–56

原文译文

Rule 5.7　标记名必须是唯一的标识符。

类别
必需（Required）
分析
可判定（Decidable），系统（System）
适用标准
C90、C99

进一步说明

标记在所有名字空间和翻译单元中必须唯一。

该标记的所有声明都必须指定同一个类型。

只有当标记声明在一个头文件中，而该头文件又被多个源文件包含时，本规则才允许同一标记有多处完整声明。

理由

重复使用标记名可能使开发者产生混淆。

在 C90 中，重复使用标记名还涉及未定义行为，尽管 C 标准的附录并未将它列出。C99 在 §6.7.2.3 中将这一未定义行为列为约束。

例外

标记名可以与同它相关联的 typedef 名相同。

原书示例

struct stag
{
  uint16_t a;
  uint16_t b;
};

struct stag a1 = { 0, 0 };   /* Compliant - compatible with above        */
union  stag a2 = { 0, 0 };   /* Non-compliant - declares different type
                              * from struct stag.
                              * Constraint violation in C99              */

下面的示例还违反了 Rule 5.3。

struct deer
{
  uint16_t a;
  uint16_t b;
};

void foo ( void )
{
  struct deer
  {
    uint16_t a;
  };                         /* Non-compliant - tag "deer" reused        */
}

typedef struct coord
{
  uint16_t x;
  uint16_t y;
} coord;                     /* Compliant by Exception                   */

struct elk
{
  uint16_t x;
};

struct elk       /* Non-compliant - declaration of different type
                  * Constraint violation in C99                          */
{
  uint32_t x;
};

另见

Rule 5.6。

原书代码注释中译（按出现顺序）　a1 与上面的类型相容，符合；a2 使用不同于 struct stag 的类型，在 C99 中违反约束。内层重用了 deer，不符合；coord 适用例外，符合。elk 的后一个声明指定了不同的类型，不符合，在 C99 中违反约束。
