Rule 19.2 · 区分联合体同成员读回与跨成员读取

底本定位 PDF／印刷 162–163／154–155。

原文译文

Rule 19.2　不应使用 union 关键字。

C90 [未定义 39、40；实现定义 27]；C99 [未指定 10；未定义 61、62]

类别
建议（Advisory）
分析
可判定（Decidable），单一翻译单元（Single Translation Unit）
适用标准
C90、C99

理由

写入联合体的一个成员，然后读回同一成员，其行为有明确定义。

但是，如果写入一个成员后读取另一个成员，行为取决于两个成员的相对大小：

  • 如果读出的成员比写入的成员宽，则读出的值是未指定的；
  • 否则，该值由实现定义。

C 标准允许通过类型为 unsigned char 数组的另一个成员访问联合体成员的字节。但由于可能访问到具有未指定值的字节，所以不应使用联合体。

如果不遵循本条，需要查明的行为包括：

  • 填充：联合体末尾插入了多少填充；
  • 对齐：联合体内若有结构体，其各个成员如何对齐；
  • 字节序：一个字的最高有效字节存储在最低还是最高的内存地址；
  • 位序：一个字节内的位如何编号，以及位如何分配给位域。

原书示例

在这个不合规的示例中，向联合体存入一个 16 位值，却从中读出一个 32 位值，结果是返回了一个未指定的值。

uint32_t zext ( uint16_t s )
{
  union
  {
    uint32_t ul;
    uint16_t us;
  } tmp;

  tmp.us = s;
  return tmp.ul;   /* unspecified value */
}

原书代码注释中译（依次）： 未指定的值。
