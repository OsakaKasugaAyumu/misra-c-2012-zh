Rule 7.4 · 字符串字面量与指向 const 的指针

底本定位 §8.7 · PDF 70–71／印刷 62–63

原文译文

Rule 7.4　除非对象的类型是“指向 const 限定的 char 的指针”，否则不得将字符串字面量赋给该对象。

C90 [未定义 12]，C99 [未指定 14；未定义 30]

类别
必需（Required）
分析
可判定（Decidable），单一翻译单元（Single Translation Unit）
适用标准
C90、C99

进一步说明

不得尝试直接修改字符串字面量或宽字符串字面量。

对字符串字面量应用取地址运算符 & 所得的结果，不得赋给对象，除非该对象的类型是“指向由 const 限定的 char 组成的数组的指针”。

同样的考虑也适用于宽字符串字面量。不得将宽字符串字面量赋给对象，除非该对象的类型是“指向 const 限定的 wchar_t 的指针”。对宽字符串字面量应用取地址运算符 & 所得的结果，不得赋给对象，除非该对象的类型是“指向由 const 限定的 wchar_t 组成的数组的指针”。

理由

任何试图修改字符串字面量的操作都会导致未定义行为。例如，有些实现可能把字符串字面量存放在只读存储器中；在这种情况下，尝试修改它将会失败，并且还可能引发异常或使程序崩溃。

本规则与其他规则配合使用时，能够防止字符串字面量被修改。

对于具有相同结尾的字符串字面量，C99 明确不规定它们是否存储在不同的内存位置。因此，即使一次修改字符串字面量的尝试看起来成功了，也可能无意中改动了另一个字符串字面量。

原书示例

下面的示例展示了直接修改字符串字面量的尝试。

"0123456789"[0] = '*';   /* Non-compliant                                */

以下示例说明如何防止字符串字面量被间接修改。

/* Non-compliant - s is not const-qualified */
char *s = "string";

/* Compliant - p is const-qualified; additional qualifiers are permitted */
const volatile char *p = "string";

extern void f1 ( char *s1 );

extern void f2 ( const char *s2 );

void g ( void )
{
  f1 ( "string" );       /* Non-compliant - parameter s1 is not
                          * const-qualified                              */
  f2 ( "string" );       /* Compliant                                    */
}

char *name1 ( void )
{
  return ( "MISRA" );    /* Non-compliant - return type is not
                          * const-qualified                              */
}

const char *name2 ( void )
{
  return ( "MISRA" );    /* Compliant                                    */
}

另见

Rule 11.4、Rule 11.8。

原书代码注释中译（按出现顺序）　直接写入不符合。s 所指的字符不带 const 限定，不符合；p 所指的字符带 const，还可以有其他限定，符合。s1 所指字符不带 const，不符合；传给 f2 符合。name1 返回指向未受 const 限定的字符的指针，不符合；name2 符合。

源页核对： PDF 71：原注以指针名描述 const；从声明看，限定的是所指字符而不是指针对象本身。原代码和英文注释保留，二者在自编示例中分开验证。
