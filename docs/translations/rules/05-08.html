Rule 5.8 · 外部链接定义的名字唯一性

底本定位 §8.5 · PDF 64／印刷 56

原文译文

Rule 5.8　用于定义具有外部链接的对象或函数的标识符必须唯一。

类别
必需（Required）
分析
可判定（Decidable），系统（System）
适用标准
C90、C99

进一步说明

用作外部标识符的标识符，不得在任何名字空间或翻译单元中另作他用，即使它在另一处指代的是一个无链接的对象也不例外。

理由

以这种方式要求标识符名唯一，有助于避免混淆。无链接对象的标识符本身不必唯一，因为它们产生这类混淆的风险很小。

原书示例

在下面的示例中，file1.c 和 file2.c 都属于同一个项目。

/* file1.c */
int32_t   count;           /* "count" has external linkage             */
void foo ( void )          /* "foo" has external linkage               */
{
  int16_t index;           /* "index" has no linkage                   */
}

/* file2.c */
static void foo ( void )   /* Non-compliant - "foo" is not unique
{                           * (it is already defined with external
                            * linkage in file1.c)                      */
  int16_t count;           /* Non-compliant - "count" has no linkage
                            * but clashes with an identifier with
                            * external linkage                         */
  int32_t index;           /* Compliant - "index" has no linkage       */
}

另见

Rule 5.3。

原书代码注释中译（按出现顺序）　第一个文件的 count 与 foo 具有外部链接，index 无链接。第二个文件的 foo 因第一个文件已定义外部同名函数而不唯一；局部 count 虽无链接，却与外部名冲突。两个 index 都无链接，符合。
