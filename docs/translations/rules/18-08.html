Rule 18.8 · 变长数组的类型与长度求值时机

底本定位 PDF／印刷 160–161／152–153。

原文译文

Rule 18.8　不得使用变长数组类型。

C99 [未指定 21；未定义 69、70]

类别
必需（Required）
分析
可判定（Decidable），单一翻译单元（Single Translation Unit）
适用标准
C99

理由

在块内或函数原型中声明数组时，如果所指定的长度不是整数常量表达式，所指定的就是变长数组类型。它通常实现为栈上大小可变的对象，因此使用它可能导致无法静态确定必须为栈预留多少内存。

如果变长数组的大小为负数或为零，行为就未定义。

如果在某种上下文中要求一个变长数组类型与另一数组类型兼容（后者本身也可能是变长数组），两种数组类型的大小就必须相同。此外，各个大小表达式都必须求得正整数值。若不满足这些条件，行为就未定义。

如果在 sizeof 运算符的操作数中使用变长数组类型，在某些情况下，是否对数组大小表达式求值是未指定的。

变长数组类型的每个实例，其大小在生存期开始时就已固定。这可能产生让人困惑的行为，例如：

void f ( void )
{
  uint16_t n = 5;

  typedef uint16_t Vector[ n ];  /* An array type with 5 elements     */

  n = 7;

  Vector   a1;                   /* An array type with 5 elements     */

  uint16_t a2[ n ];              /* An array type with 7 elements     */
}

原书代码注释中译（依次）： （1）有五个元素的数组类型。 （2）有五个元素的数组类型。 （3）有七个元素的数组类型。

原书示例

变长数组的任何用法都不符合本条。下例展示了使用变长数组可能导致的一些未定义行为。

void f ( int16_t n )
{
  uint16_t vla[ n ];            /* Non-compliant - Undefined if n <= 0 */
}

void g ( void )
{
  f ( 0 );                      /* Undefined */
  f ( -1 );                     /* Undefined */
  f ( 10 );                     /* Defined   */
}

原书代码注释中译（依次）： （1）不合规：当 n 小于或等于 0 时行为未定义。 （2）行为未定义。 （3）行为未定义。 （4）行为有定义。

void h ( uint16_t n,
         uint16_t a[ 10 ][ n ] )    /* Non-compliant */
{
  uint16_t ( *p )[ 20 ];

  /* Undefined unless n == 20: incompatible types otherwise */
  p = a;
}

原书代码注释中译（依次）： （1）不合规。 （2）除非 n 等于 20，否则类型不兼容，行为未定义。
