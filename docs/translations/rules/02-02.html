Rule 2.2 · 死代码

底本定位 §8.2 · PDF 49–50／印刷 41–42

原文译文

Rule 2.2　不得含有死代码。

[IEC 61508-7 第 C.5.10 节]，[ISO 26262-6 第 9.4.5 节]，[DO-178C 第 6.4.4.3.c 节]

类别
必需（Required）
分析
不可判定（Undecidable），系统（System）
适用标准
C90、C99

进一步说明

凡是会执行、但删除后不会影响程序行为的操作，均构成死代码。由语言扩展引入的操作，一律视为会对程序行为产生影响。

注： 嵌入式系统的行为往往不仅取决于它执行什么动作，也取决于执行动作的时间。

注： 不可达代码不属于死代码，因为它不能被执行。

理由

存在死代码可能表明程序逻辑有误。由于编译器可能删除死代码，它的存在还可能造成困惑。

例外

强制转换为 void 被视为表明某个值是有意不使用的。因此，该转换本身不是死代码。它也被视为使用了其操作数，所以该操作数同样不是死代码。

原书示例

在本例中，假定 p 指向的对象在其他函数中会被使用。

extern volatile uint16_t v;

extern char *p;

void f ( void )
{
  uint16_t  x;

  ( void ) v;      /* Compliant     - v is accessed for its side effect
                    *                 and the cast to void is permitted
                    *                 by exception                       */
  ( int32_t ) v;   /* Non-compliant - the cast operator is dead          */
  v >> 3;          /* Non-compliant - the >> operator is dead            */
  x = 3;           /* Non-compliant - the = operator is dead
                    *               - x is not subsequently read         */
  *p++;            /* Non-compliant - result of * operator is not used   */
  ( *p )++;        /* Compliant     - *p is incremented                  */
}

原书代码注释中译（依次）： ① 合规：访问 v 是为了产生副作用，例外允许转为 void。② 不合规：强制转换运算符是死代码。③ 不合规：>> 运算符是死代码。④ 不合规：赋值运算符 = 是死代码，之后并未读取 x。⑤ 不合规：未使用 * 运算符的结果。⑥ 合规：*p（即 p 所指对象的值）被递增。

在下面的合规示例中，__asm 关键字是语言扩展，不是函数调用操作，因此不是死代码：

__asm ( "NOP" );

在下例中，函数 g 不含死代码；由于它不含任何操作，函数本身也不是死代码。然而，对它的调用是死代码，因为删除该调用不会影响程序行为。

void g ( void )
{
  /* Compliant - there are no operations in this function */
}

void h ( void )
{
  g ( );   /* Non-compliant - the call could be removed   */
}

原书代码注释中译： g 的函数体合规——其中没有操作。h 中的调用不合规——可以删除这次调用。
