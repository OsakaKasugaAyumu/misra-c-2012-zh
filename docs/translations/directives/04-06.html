Dir 4.6 · 用类型名表明位宽和符号性

底本定位 §7.4 · PDF 36–38／印刷 28–30，止于 Dir 4.7 标题前。

原文译文

Dir 4.6　应使用能表明大小和符号性的 typedef 类型名，代替基本数值类型。

类别
建议（Advisory）
适用标准
C90、C99

进一步说明

不应使用 char、short、int、long、long long（C99）、float、double 和 long double 这些基本数值类型，而应使用指定长度的 typedef 类型名。

对于 C99，应使用 <stdint.h> 提供的类型。对于 C90，应定义并使用等价的类型。

除非底层类型在该实现上确实具有所指定的长度，否则不得将类型定义为该长度。

声明位域时，不必使用 typedef 类型名。

例如，在一个 32 位 C90 实现上，以下定义可能是合适的：

typedef signed   char   int8_t;
typedef signed   short  int16_t;
typedef signed   int    int32_t;
typedef signed   long   int64_t;

typedef unsigned char   uint8_t;
typedef unsigned short  uint16_t;
typedef unsigned int    uint32_t;
typedef unsigned long   uint64_t;

typedef          float  float32_t;
typedef          double float64_t;
typedef long     double float128_t;

理由

在分配多少内存很重要的场合，使用指定长度的类型，可以清楚地看出为每个对象预留了多少存储空间。

遵守本准则并不能保证可移植性，因为 int 类型的大小可能决定一个表达式是否会发生整数提升。例如，如果 int 在实现中是 16 位，类型为 int16_t 的表达式就不会被提升；如果 int 在实现中是 32 位，该表达式就会被提升。附录 C 中有关整数提升的部分对此有更详细的讨论。

注： 如果定义的定长类型与实现中底层类型的实际大小不符，那么无论就存储需求还是就可移植性而言，都会适得其反。应注意避免把类型的大小定义错。

如果抽象类型建立在定长类型之上，就不必再在抽象类型中指明大小或符号性；指明这些信息甚至可能并不合适。例如，以下代码定义了一个以千克为单位表示质量的抽象类型，但没有指明其大小或符号性：

typedef uint16_t mass_kg_t;

与标准库或项目无法控制的代码对接时，不应用本准则可能更为合适。

例外

  1. 可在 typedef 中使用基本数值类型来定义指定长度的类型。
  2. 对于函数 main，其返回类型可以用 int，而不必使用 typedef 类型名。因此，允许 int main (void)。
  3. 对于函数 main，其输入参数 argc 可以用 int，而不必使用 typedef 类型名。
  4. 对于函数 main，其输入参数 argv 可以用 char，而不必使用 typedef 类型名。

因此，允许 int main( int argc, char *argv[] )（C99 §5.1.2.2.1）。

原书示例

/* Non-compliant - int used to define an object                      */
int x = 0;

/* Compliant     - int used to define specific-length type           */
typedef int SINT_16;

/* Non-compliant - no sign or size specified                         */
typedef int speed_t;

/* Compliant     - further abstraction does not need specific length */
typedef int16_t torque_t;

原书代码注释（译），依次为：① 不合规——用 int 定义对象；② 合规——用 int 定义指定长度的类型；③ 不合规——未指明符号性或大小；④ 合规——进一步抽象时不需要再指定长度。
