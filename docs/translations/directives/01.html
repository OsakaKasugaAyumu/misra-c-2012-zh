7　指令

7.1　实现

Dir 1.1　程序输出所依赖的任何实现定义行为，都必须记录在文档中，并为开发者所理解。

C90 [附录 G.3]，C99 [附录 J.3]

类别
必需（Required）
适用标准
C90、C99

进一步说明

本文件的附录 G 分别针对 C90 和 C99 列出了同时满足以下条件的实现定义行为：

  • 被认为可能导致程序以非预期的方式运行；并且
  • 即使程序符合所有其他 MISRA C 准则，这些行为仍可能存在于程序中。

在这些实现定义行为中，凡是程序输出所依赖的，都必须：

  • 记录在文档中；并且
  • 为开发者所理解。

注： 符合标准的实现必须在文档中说明它如何处理每一种实现定义行为。如果文档有缺漏，应向该实现的开发者咨询。

理由

重要的是，要知道程序的输出确实是设计者想要的，而不是碰巧产生的。

下面说明安全相关嵌入式软件很可能依赖的一些较常见的实现定义行为。

核心行为

大多数程序很可能都需要了解的基本实现定义行为包括：

  • 如何识别翻译过程中产生的诊断消息；
  • 函数 main 的类型；在独立式实现中，它通常声明为 void main (void)；
  • 标识符中有意义的字符数——配置分析工具以检查 Rule 5.2 时需要此项信息；
  • 源字符集和执行字符集；
  • 各整数类型的大小；
  • #include 中指定的名称如何映射到文件名，以及如何在宿主文件系统中定位该文件。

扩展

嵌入式系统经常使用扩展来访问外设，或将对象置于具有特殊属性的存储区域，例如 Flash EEPROM 或可快速访问的 RAM。符合标准的实现可以提供扩展，前提是这些扩展不改变任何严格符合标准的程序的含义。

某些 C90 实现提供的扩展可能实现了 C99 的一部分特性。

实现提供扩展的方式包括：

  • #pragma 预处理指令或 _Pragma 运算符（后者仅适用于 C99）；
  • 新的关键字。

标准库

标准库的实现中，以下方面可能很重要：

  • 使用某些标准库函数时赋给 errno 的值；
  • 时钟函数和时间函数的实现方式；
  • 文件系统的特性。

应用程序二进制接口

有时需要将 C 代码与汇编语言对接，例如在执行速度至关重要的地方提高速度。也可能需要对接由不同编译器生成的代码，这些代码甚至可能使用不同语言编写。

编译器的应用程序二进制接口（ABI）提供了完成这项工作所需的信息，其中包括某些实现定义行为。它通常规定：

  • 函数参数如何通过寄存器和栈传递；
  • 函数的返回值如何传回；
  • 函数必须保留哪些寄存器；
  • 具有自动存储期的对象如何分配到栈帧中；
  • 每种数据类型的对齐要求；
  • 结构体如何布局，以及位域如何分配到存储单元中。

有些处理器有标准 ABI，所有实现都会使用它。如果没有标准 ABI，实现就会提供自己的 ABI。

整数除法

在 C90 中，进行有符号整数除法或取余运算时，如果任一操作数为负，相应的商既可以向下取整，也可以向零取整。在 C99 中，保证向零取整。

浮点实现

浮点类型的实现方式可能对程序行为有显著影响，例如：

  • 可表示的数值范围，以及存储这些值时的精度；
  • 浮点运算后的舍入方向；
  • 转换到较窄的浮点类型或整数类型时的舍入方向；
  • 出现下溢、上溢或非数（NaN）时的行为；
  • 发生定义域错误或值域错误时库函数的行为。
