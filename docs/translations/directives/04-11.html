Dir 4.11 · 检查传给库函数的值

底本定位 §7.4 · PDF 41–42／印刷 33–34，从 Dir 4.11 标题起，止于 Dir 4.12 标题前。

原文译文

Dir 4.11　必须检查传给库函数的值是否有效。

C90 [Undefined 60, 63, 96; Implementation 45–47]
C99 [Unspecified 30, 31, 44, 48–50; Undefined 102, 103, 107, 112, 180, 181, 183, 187, 189; Implementation J.3(8–11)]

类别
必需（Required）
适用标准
C90、C99

进一步说明

项目的性质和组织方式决定哪些库，以及这些库中的哪些函数，应当受本指令约束。

理由

C 标准并不要求标准库中的许多函数检查传入参数的有效性。即便标准要求检查，或者编译器开发者声称会检查参数，也不能保证这些检查足够充分。

同样，其他库的函数接口说明未必写明这些函数会做哪些检查。即便写明了，也有可能检查得不充分。

对于输入域受限的所有库函数，无论来自标准库、第三方库还是内部开发的库，程序员都必须对输入值进行适当的检查。

标准库中，输入域受限、需要检查的函数有以下例子：

  • <math.h> 中的许多数学函数，例如：
    • 不得将负数传给 sqrt 或 log；
    • fmod 的第二个参数不应为零；
  • 在某些实现中，传给 toupper 的实参如果不是小写字母，可能得到意外结果（tolower 的情形与之类似）；
  • 如果传入无效值，<ctype.h> 中的字符分类函数会表现出未定义行为；
  • 对最小的负整数调用 abs 会产生未定义行为。

尽管 <math.h> 中的大多数数学库函数都规定了允许的输入域，但发生定义域错误时，函数的返回值可能因编译器而异。因此，对这些函数而言，预先检查输入值的有效性尤为重要。

程序员应当明确所用函数在实际使用中应有哪些合理的输入域约束（接口说明中可能记载了这些约束，也可能没有），并作适当检查，确保一个或多个输入值落在该域内。当然，如有需要，还可以根据参数代表什么、怎样的取值范围对它才合理，进一步限定取值。

满足本准则要求的方式不止一种，包括：

  • 在调用函数之前检查这些值；
  • 在被调用的库函数内部检查这些值。这种方式特别适用于内部设计的库；对于外购库，如果供应商能够证明库中内置了这些检查，也可以采用这种方式；
  • 编写函数的包装版本，由包装函数先检查，再调用原函数；
  • 通过静态分析或推理，证明输入参数不可能取到无效值。
