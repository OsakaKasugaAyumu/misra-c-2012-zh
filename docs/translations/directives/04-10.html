Dir 4.10 · 防止头文件内容被重复包含

底本定位 §7.4 · PDF 40–41／印刷 32–33，止于 Dir 4.11 标题前。

原文译文

Dir 4.10　必须采取预防措施，防止头文件的内容被多次包含。

类别
必需（Required）
适用标准
C90、C99

理由

当一个翻译单元含有层层嵌套、关系复杂的头文件时，同一个头文件可能被包含多次。即使没有造成其他后果，这也可能使人困惑。如果重复包含导致多重定义或相互冲突的定义，就可能造成未定义行为或错误行为。

原书示例

/* file.h */
#ifndef FILE_H
/* Non-compliant - does not #define FILE_H */
#endif

原书代码注释（译）：文件名为 file.h；“不合规——没有用 #define 定义 FILE_H”。

为便于检查，应当采用以下两种形式之一，保护头文件的内容，使其不会被多次包含：

<start-of-file>
#if !defined ( identifier )
#define identifier
  /* Contents of file */
#endif
<end-of-file>

<start-of-file>
#ifndef identifier
#define identifier
  /* Contents of file */
#endif
<end-of-file>

两段原书代码中的标记和注释（译）：<start-of-file> 表示“文件开头”，<end-of-file> 表示“文件结尾”；identifier 表示“标识符”，块内注释为“文件内容”。

注： 用来检查并记录某个头文件是否已经被包含的标识符，在项目的所有头文件中必须唯一。

注： 在上述形式中的任何位置都允许写注释。
