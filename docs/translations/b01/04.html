4.1 培训

为确保编写 C 源代码的人员具备适当的技能与胜任能力，应当在以下方面提供正规培训：

  • 使用 C 语言开发嵌入式应用；
  • 在高完整性系统和安全相关系统中使用 C 语言。

由于编译器和静态分析工具都是复杂的软件，还应考虑就其使用方法提供培训。对静态分析工具而言，还有可能获得专门针对使用这些工具检查 MISRA C 的培训。

4.2 了解编译器

本文件所说的“编译器”，即 ISO C 标准 [2]、[8] 所称的“实现”，既包括编译器本身，也包括相关工具，如链接器、库管理器和可执行文件格式转换工具。

编译器可能提供多种控制其行为的选项。理解各选项的作用很重要，因为是否使用它们可能影响：

  • 哪些语言扩展可用；
  • 编译器对 ISO C 标准的符合程度；
  • 程序需要的资源，特别是处理时间和存储空间；
  • 暴露编译器缺陷的可能性，例如执行复杂的深度优化代码变换时，就可能暴露缺陷。

理解编译器如何实现 ISO C 标准称为“实现定义”的语言特性很重要。了解编译器可能提供的各种语言扩展也很重要。

编译器开发者可能维护一份影响该编译器的已知缺陷清单，并列出可用的规避方法。在启动使用该编译器的项目前先了解清单内容，显然会有益处。如果开发者不提供此类清单，就应当自行维护一份：每当发现缺陷或疑似缺陷并向编译器开发者报告时，便记入清单。

4.3 了解静态分析工具

应当查阅项目所用每一种静态分析工具的文档，以了解：

  • 如何配置分析器，使其与编译器的实现定义行为一致，例如与各整数类型的大小一致；
  • 分析器能够检查哪些 MISRA C 准则（§5.3）；
  • 能否配置分析器，使其处理项目将使用的语言扩展；
  • 能否调整分析器的行为，在分析时间与分析精度之间取得不同的平衡。

工具开发者可能维护一份影响该工具的已知缺陷清单，并列出可用的规避方法。在启动使用该工具的项目前先了解清单内容，显然会有益处。如果工具开发者不提供此类清单，就应当自行维护一份：每当发现缺陷或疑似缺陷并向工具开发者报告时，便记入清单。
