2.1 C 语言为何广受使用

C 程序设计语言之所以广受使用，是因为：

  • 许多处理器都很容易找到可用的 C 编译器；
  • C 程序可以编译成高效的机器码；
  • C 语言由国际标准定义；
  • 它提供了访问目标处理器输入／输出功能的机制，既可直接访问，也可借助语言扩展访问；
  • 人们已积累了大量在关键系统中使用 C 的经验；
  • 静态分析工具和测试工具对 C 的支持很广泛。

2.2 C 语言的不足

尽管 C 广受使用，它仍有若干不足，下面分节讨论。

2.2.1 语言定义

ISO 标准并未完整规定语言的所有细节，而是把一些方面交由实现决定。这是有意为之，部分原因是要支持许多既有实现，而它们所针对的处理器差异很大。

因此，语言中存在一些情形，其中：

  • 行为未定义；
  • 行为未指定；
  • 实现可以自行选择行为，但前提是将该行为记入文档。

依赖未定义行为或未指定行为的程序，不能保证其行为可预测。

过度依赖实现定义行为的程序可能很难移植到其他目标平台。如果无法将分析器配置为处理某种实现定义行为，这种行为的存在也可能妨碍静态分析。

2.2.2 语言误用

C 程序固然可以写得结构清晰、易于理解，但 C 也很容易让程序员写出晦涩难懂的代码。

运算符的规定使编译器很难检出某些编程错误。例如，下面两个代码片段都是完全合法的，因此编译器不可能知道程序员是否误将其中一个写成了另一个：

if ( a == b )   /* tests whether a and b are equal                */
if ( a = b )    /* assigns b to a and tests whether a is non-zero */

原书注释中译： 第一行检查 a 与 b 是否相等；第二行把 b 赋给 a，再检查 a 是否非零。

2.2.3 对语言的误解

程序员常会误解语言的某些方面。例如，C 的运算符比其他一些语言多，因而有很多不同的运算符优先级，其中有些并不直观。

C 的类型规则也可能让熟悉强类型语言的程序员感到困惑。例如，操作数可能被“提升”为更宽的类型，这意味着运算所得结果的类型不一定与操作数的类型相同。

2.2.4 运行时错误检查

C 程序可以编译成紧凑、高效的机器码，但代价是运行时检查十分有限。对于算术异常（例如除零）、溢出、指针是否有效或数组越界等常见问题，C 程序通常不提供运行时检查。C 的设计理念是由程序员负责显式实施这类检查。
