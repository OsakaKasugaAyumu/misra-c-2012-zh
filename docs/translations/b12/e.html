E.1 自动生成代码的准则类别

对大多数 MISRA C 准则，自动生成代码与人工编写代码的类别相同。

本节列出类别不同的准则。为方便起见，将理由相近的准则列在一起。

E.1.1 附加类别

自动生成代码采用一个附加的准则类别：

E.1.1.1 可读性

若一条准则归为“可读性”，并且自动生成的代码不打算交由程序员阅读、审查或修改，就不必遵守该条准则。若有人使用该代码，则类别仍与人工编写代码相同。

E.1.2 标识符隐藏

准则类别
Rule 5.3建议

自动代码生成器能够跟踪自己使用的标识符，不应因标识符复用而产生混淆。因此，该准则用于自动生成代码时为建议类。

将人工编写的代码插入自动生成代码，或反过来插入时，标识符可能在代码生成器不知情的情况下被隐藏。因此，只要被隐藏的标识符或隐藏其他标识符的那个标识符是在人工编写的代码中声明的，本准则仍为必需类。

E.1.3 八进制常量

准则类别
Rule 7.1建议

自动代码生成器不大可能无意中生成八进制常量。

E.1.4 具有外部链接属性的兼容声明

准则类别
Rule 8.4建议
Rule 8.5建议

这些准则要求：

  • 定义具有外部链接属性的对象或函数时，有兼容的声明可见；
  • 每个具有外部链接属性的对象或函数只在一个文件中声明。

两项要求共同提供一种机制，确保使用该对象或函数声明的所有翻译单元，其使用方式都与定义兼容。不过，这不是保证兼容性的唯一策略。例如，自动代码生成器可以在数据字典中保存各对象或函数的声明，在每个需要它的翻译单元中使用该声明。

E.1.4.1 restrict 类型限定符
准则类别
Rule 8.14建议

若自动代码生成器能够确定两个指针不互为别名，它可能希望使用 restrict 类型限定符。

E.1.5 本质类型

准则类别
Rule 10.1建议
Rule 10.2建议
Rule 10.3建议
Rule 10.4建议
Rule 10.6建议
Rule 10.7建议
Rule 10.8建议
Rule 14.4建议
Rule 20.8建议

本质类型概念是避免整数提升和通常算术转换相关问题的一种方法。自动代码生成器可以采用同样有效的其他方法来避免这些问题。此外，它既知道 C 的隐式类型转换规则，也知道目标机器上各类型的大小。

因此，与本质类型相关的规则用于自动生成代码时，都归为建议类。

E.1.6 循环计数器

准则类别
Rule 14.1建议

自动代码生成器了解所用的浮点实现，因而知道采用浮点循环计数器会有什么影响。

E.1.7 标号与 goto

准则类别
Rule 15.2建议
Rule 15.3建议

自动代码生成器可能需要生成向后跳转，例如在实现状态机时。它极少会生成跳入所插入人工代码块的跳转，因此应该能够避免跳过初始化。

E.1.8 switch 语句

准则类别
Rule 16.1建议
Rule 16.2建议
Rule 16.3建议
Rule 16.4建议
Rule 16.5建议
Rule 16.6建议
Rule 16.7建议

如果自动代码生成器确定可以通过优化省去模型所指示的 default 子句，例如控制表达式的每个值都已被 case 子句覆盖，那么只有在生成的 C 代码中插入注释、解释为什么没有 default 子句时，才可以这样做。这条注释可以在论证 MISRA C 合规性时接受审查和认可。

自动代码生成器能够处理从一个 switch 子句贯穿到后续子句的情况。

某些不常见的 switch 语句，例如控制表达式为本质布尔型，或只有一个 switch 子句，在人工编写的代码中可能意味着错误，在自动生成的代码中却可能是必要或可取的。

这些准则是为开发者和审查人员而设的。

若在插入的代码中声明了具有内部链接属性的标识符，则在整个翻译单元内，Rule 5.9 应用于该标识符时为建议类。

若把代码插入自动生成的 for 循环，且不合规是由插入的代码造成的，则就该不合规而言，Rule 14.2 为必需类。

E.2 对自动代码生成工具的文档要求

自动代码生成工具的开发者必须为本节所列的每一项提供文档。

E.2.1 实现定义行为与语言扩展

根据 Dir 1.1，自动生成代码所依赖的任何实现定义行为，其使用情况都必须形成文档。

根据 Rule 1.2，自动生成代码对语言扩展的使用，以及用以保证这些扩展得到正确使用的方法，都必须形成文档。

根据 Dir 4.2，自动生成代码使用汇编语言的情况必须形成文档。

E.2.2 本质类型模型

若自动代码生成器不使用本质类型模型，它用来替代该模型的策略必须形成文档。

E.2.3 运行时错误

按照 Dir 4.1 的要求，自动代码生成器应选择合适的代码生成策略，尽量降低运行时失效的可能性。若仍可能发生运行时失效，代码生成器所用的错误处理策略必须形成文档。由于很可能需要人工编写的代码来处理错误，错误处理接口也必须作为整体错误处理策略的一部分形成文档。
