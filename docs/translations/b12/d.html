原文译文

ISO C 标准所定义的 C 语言有若干弱点和不一致之处。不幸的是，表达式的标准类型并不总能充分描述其所表示的数据的本质。例如：

  • 整数提升。各种整数类型的行为并不一致。由于整数提升，本来无符号的表达式（如 unsigned char + unsigned char）其标准类型通常是 signed int。
  • 整数常量。整数常量只有 int、long、long long 的有符号或无符号类型。这使得保持类型一致更加困难（例如将常量作为函数实参时）。
  • 字符常量。字符常量（如 'x'）的标准类型被定义为 int，不是 char。这模糊了字符数据（即“字符”）与数值数据（即“数值”）之间的区别。
  • 逻辑表达式。C90 没有布尔类型。C99 引入了 _Bool，但由于向后兼容的原因，相等运算符（==、!=）、关系运算符（<、<=、>=、>）和逻辑运算符（&&、||、!）的结果仍是 int 而非 _Bool。
  • 位域。ISO C 没有定义一种位域类型。因此，例如，不可能强制转换到位域类型。ISO C 为位域定义的标准类型是 _Bool、signed int 或 unsigned int 之一。类型写作 int 的位域，其符号性由实现定义。
  • 枚举。枚举的类型由实现定义。实现可以自由选用能够表示该枚举的任何整数类型。若枚举包含负值，该类型就是有符号整数类型；若仅含非负值，则既可以是有符号整数类型，也可以是无符号整数类型。
  • 枚举常量。无论用什么类型实现枚举，枚举常量始终具有 int 类型。

D.1 表达式的本质类型类别

为缓解上述问题，MISRA C:2012 引入了本质类型的概念。表达式的本质类型类别是下列之一：

  • 本质布尔型；
  • 本质字符型；
  • 本质枚举型；
  • 本质有符号型；
  • 本质无符号型；
  • 本质浮点型。

下表给出标准整数类型到本质类型类别的映射。注：C99 实现可以提供扩展整数类型，应按照各自的等级和符号性把它们安排在适当位置（见 C99 §6.3.1.1）。

描述有符号和无符号类型集合时，等级的概念尤为重要。有符号和无符号 long long 同处“最高”等级，有符号和无符号 char 同处“最低”等级。在 ISO C99 标准中，“等级”一词仅用于整数类型。

只有在标准类型为 signed int 或 unsigned int 的表达式中，表达式的本质类型才可能不同于标准 C 类型（标准类型）。

以下各段规定本质类型与标准类型不同的具体情形。

D.2 字符数据的本质类型

标准类型为 char（即单字节字符）的对象，具有本质字符类型。

D.3 最低等级有符号类型和最低等级无符号类型（STLR 与 UTLR）

本质类型模型引入了最低等级有符号类型（STLR）和最低等级无符号类型（UTLR）的概念。这样，整数常量表达式和位域就能以等级低于 int 的本质类型参与表达式。对整数常量表达式而言，这省去了将表达式本身或其操作数强制转换到较低等级类型的麻烦。同样，如果实现不允许位域的类型等级低于 int，也能在某些情况下免去对位域的强制转换。

  1. STLR 是能表示给定整数常量表达式的值，或能同时表示给定位域的最大值和最小值的、等级最低的有符号类型。
  2. UTLR 是能表示给定整数常量表达式的值，或能表示给定位域最大值的、等级最低的无符号类型。

D.4 位域的本质类型

位域的本质类型由下列从上到下第一项适用的条件确定：

  1. 若位域以本质布尔类型实现，则为本质布尔型；
  2. 若位域以有符号类型实现，则为能够表示该位域的 STLR；
  3. 若位域以无符号类型实现，则为能够表示该位域的 UTLR。

D.5 枚举的本质类型

需要区分两种枚举：

  1. 有名枚举类型：枚举带有标记，或用在任何对象、函数或类型的定义中。
  2. 匿名枚举类型：枚举没有标记，也不用于任何对象、函数或类型的定义。通常用于定义一组常量，这些常量可以相关，也可以互不相关。

一个有名枚举类型不同于所有其他有名枚举类型，即便在内层作用域中用完全相同的标记和枚举常量声明也不例外。本文档以 enum<i> 表示每个有名枚举类型，不同类型的 i 各不相同。

用 typedef 为有名枚举类型建立的别名仍表示原来的有名枚举类型，不是新类型。

匿名枚举类型的本质类型就是它的标准类型。

下列声明涉及的都是有名枚举类型；各声明中的枚举类型彼此不同，本质类型也各不相同：

      enum ETAG { A, B, C };
typedef enum  { A, B, C } ETYPE;
typedef enum ETAG { A, B, C } ETYPE;
      enum    { A, B, C } x;

以下两个 typedef 都指向同一个 enum<i>：

typedef enum  { A, B, C } ETYPE;
typedef ETYPE          FTYPE;

D.6 字面常量的本质类型

ISO C99 标准定义了下列具有整数类型的常量：

  • 整数常量；
  • 枚举常量；
  • 字符常量。

注：具有整数类型的常量不一定是整数常量。

整数常量

  1. 若整数常量的标准类型是 signed int，其本质类型是 STLR；
  2. 若整数常量的标准类型是 unsigned int，其本质类型是 UTLR。

枚举常量

在 C 中，枚举常量的标准类型始终为 int，无论枚举用什么类型实现，也无论用于定义该常量值的初始化表达式是什么类型。例如，即使用无符号值（如 500U）初始化枚举常量，该常量的标准类型仍视为 signed int。

枚举常量的本质类型按下列方法确定：

  1. 若枚举定义了有名枚举类型，则其枚举常量的本质类型为 enum<i>；
    1. 1.1 若这个有名枚举类型用于定义本质布尔类型，其枚举常量的本质类型就是本质布尔型。
  2. 若枚举定义了匿名枚举类型，则各枚举常量的本质类型为其值的 STLR。

在下面的例子中，各枚举常量和对象 x 都具有 enum<i> 的本质类型：

enum ETAG { A = 8, B = 64, C = 128 } x;

以下匿名枚举类型定义了一组常量。每个常量的本质类型为 STLR。因此，在 char 为 8 位、short 为 16 位的机器上，A 和 B 的本质类型是 signed char，而 C 的本质类型是 signed short。

enum { A = 8, B = 64, C = 128 };

字符常量

字符常量（如 'q'、'xy'）的标准类型是 int，不是 char。

  1. 若字符常量仅由一个字符组成，其本质类型为 char；
  2. 否则其本质类型与标准类型相同。

布尔常量

C99 标准没有提供显式定义 _Bool 类型常量的语法。库头文件 <stdbool.h> 使用 int 类型的常量 0 和 1 来定义 false 和 true，但后两者的本质类型为本质布尔型。如果不使用它们，或它们不可用，则可以通过显式强制转换或产生本质布尔值的运算符来声明 _Bool 类型的常量表达式。

工具还可提供其他识别本质布尔类型的方法。例如，可以配置工具使之识别：

enum Bool {False, True};

仅当表达式不用于 #if 或 #elif 预处理指令时，才适合使用强制转换定义布尔类型常量表达式（如 (_Bool)0）。在预处理指令中使用强制转换是语法错误。

D.7 表达式的本质类型

本节未列出的任何表达式，其本质类型都与标准类型相同。

逗号（,）

结果的本质类型是右操作数的本质类型。

关系（< <= >= >）、相等（== !=）和逻辑（&& || !）

表达式的结果是本质布尔型。

移位（<< >>）

  1. 若左操作数为本质无符号型：
    1. 1.1 若两个操作数都是整数常量表达式，则结果的本质类型为结果值的 UTLR；
    2. 1.2 否则，结果的本质类型为左操作数的本质类型。
  2. 否则，本质类型为标准类型。

按位取反（~）

  1. 若操作数为本质无符号型：
    1. 1.1 若操作数是整数常量表达式，则结果的本质类型为结果值的 UTLR；
    2. 1.2 否则，结果的本质类型为操作数的本质类型。
  2. 否则，本质类型为标准类型。

一元正号（+）

  1. 若操作数为本质有符号型或本质无符号型，则结果的本质类型为操作数的本质类型；
  2. 否则，本质类型为标准类型。

一元负号（-）

  1. 若操作数为本质有符号型：
    1. 1.1 若表达式是整数常量表达式，则结果的本质类型为整个表达式的 STLR；
    2. 1.2 否则，结果的本质类型为操作数的本质类型。
  2. 否则，本质类型为标准类型。

条件（?:）

  1. 若第二、第三操作数的本质类型相同，结果也具有该本质类型；
  2. 否则，若第二、第三操作数都为本质有符号型，结果的本质类型为两者中等级较高者的本质类型；
  3. 否则，若第二、第三操作数都为本质无符号型，结果的本质类型为两者中等级较高者的本质类型；
  4. 否则，本质类型为标准类型。

进行通常算术转换的运算（* / % + - & | ^）

  1. 若两个操作数都为本质有符号型：
    1. 1.1 若表达式是整数常量表达式，则结果的本质类型为结果值的 STLR；
    2. 1.2 否则，结果的本质类型为等级较高的操作数的本质类型。
  2. 否则，若两个操作数都为本质无符号型：
    1. 2.1 若表达式是整数常量表达式，则结果的本质类型为结果值的 UTLR；
    2. 2.2 否则，结果的本质类型为等级较高的操作数的本质类型。
  3. 否则，本质类型为标准类型。

与 char 相加

  1. 若一个操作数为本质字符型，另一个为本质有符号型或本质无符号型，则结果的本质类型为 char；
  2. 否则，本质类型为标准类型。

与 char 相减

  1. 若第一操作数为本质字符型，第二操作数为本质有符号型或本质无符号型，则结果的本质类型为 char；
  2. 否则，本质类型为标准类型。
