实现

编号分类准则
Dir 1.1必需程序输出所依赖的任何实现定义行为，都必须记录在文档中，并为开发者所理解。

编译与构建

编号分类准则
Dir 2.1必需所有源文件都必须在没有任何编译错误的情况下完成编译。

需求可追溯性

编号分类准则
Dir 3.1必需所有代码都必须能够追溯到已形成文档的需求。

代码设计

编号分类准则
Dir 4.1必需必须尽可能减少运行时失效。
Dir 4.2建议凡使用汇编语言之处，都应记录在文档中。
Dir 4.3必需必须对汇编语言进行封装和隔离。
Dir 4.4建议不应把成段代码“注释掉”。
Dir 4.5建议在同一名字空间中，可见范围有重叠的标识符应当能从字形上明确区分。
Dir 4.6建议应使用能表明大小和符号性的 typedef 类型名，代替基本数值类型。
Dir 4.7必需如果函数返回错误信息，就必须检查该错误信息。
Dir 4.8建议如果在某个翻译单元中从不对指向结构体或联合体的指针解引用，就应隐藏该对象的实现。
Dir 4.9建议在函数与函数式宏可以互换的场合，应优先使用函数。
Dir 4.10必需必须采取预防措施，防止头文件的内容被多次包含。
Dir 4.11必需必须检查传给库函数的值是否有效。
Dir 4.12必需不得使用动态内存分配。
Dir 4.13建议为操作某一资源而设计的函数，应按适当的顺序调用。

标准 C 环境

编号分类准则
Rule 1.1必需程序不得违反标准 C 的任何语法规则或约束，也不得超出实现的翻译限度。
Rule 1.2建议不应使用语言扩展。
Rule 1.3必需不得出现未定义行为或关键的未指定行为。

未使用的代码

编号分类准则
Rule 2.1必需项目中不得含有不可达代码。
Rule 2.2必需不得含有死代码。
Rule 2.3建议项目中不应含有未使用的类型声明。
Rule 2.4建议项目中不应含有未使用的标记声明。
Rule 2.5建议项目中不应含有未使用的宏声明。
Rule 2.6建议函数中不应含有未使用的标号声明。
Rule 2.7建议函数中不应有未使用的形参。

注释

编号分类准则
Rule 3.1必需注释内部不得使用字符序列 /* 和 //。
Rule 3.2必需不得在 // 注释中使用行拼接。

字符集与词法约定

编号分类准则
Rule 4.1必需八进制和十六进制转义序列必须有明确的终止位置。
Rule 4.2建议不应使用三字符组。

标识符

编号分类准则
Rule 5.1必需不同的外部标识符必须可区分。
Rule 5.2必需在同一作用域和同一名字空间内声明的标识符必须可区分。
Rule 5.3必需在内层作用域声明的标识符不得遮蔽在外层作用域声明的标识符。
Rule 5.4必需不同的宏标识符必须可区分。
Rule 5.5必需标识符必须能与宏名区分开。
Rule 5.6必需typedef 名必须是唯一的标识符。
Rule 5.7必需标记名必须是唯一的标识符。
Rule 5.8必需用于定义具有外部链接的对象或函数的标识符必须唯一。
Rule 5.9建议用于定义具有内部链接的对象或函数的标识符应当唯一。

类型

编号分类准则
Rule 6.1必需位域只能用适当的类型声明。
Rule 6.2必需具名的单比特位域不得具有有符号类型。

字面量与常量

编号分类准则
Rule 7.1必需不得使用八进制常量。
Rule 7.2必需凡以无符号类型表示的整数常量，都必须加上 u 或 U 后缀。
Rule 7.3必需字面量后缀中不得使用小写字母 l。
Rule 7.4必需除非对象的类型是“指向 const 限定的 char 的指针”，否则不得将字符串字面量赋给该对象。

声明与定义

编号分类准则
Rule 8.1必需必须显式指定类型。
Rule 8.2必需函数类型必须采用原型形式，并为形参命名。
Rule 8.3必需同一对象或函数的所有声明必须使用相同的名称和类型限定符。
Rule 8.4必需在定义具有外部链接属性的对象或函数时，必须有一个与之兼容的声明在该处可见。
Rule 8.5必需外部对象或函数必须只声明一次，并且只能在一个文件中声明。
Rule 8.6必需具有外部链接属性的标识符必须恰有一个外部定义。
Rule 8.7建议如果函数或对象只在一个翻译单元中被引用，则不应将其定义为具有外部链接属性。
Rule 8.8必需具有内部链接属性的对象和函数，其所有声明都必须使用 static 存储类说明符。
Rule 8.9建议如果对象的标识符只出现在一个函数中，则该对象应当定义在块作用域内。
Rule 8.10必需内联函数必须以 static 存储类声明。
Rule 8.11建议声明具有外部链接属性的数组时，应当显式指定其大小。
Rule 8.12必需在同一枚举项列表中，隐式指定的枚举常量的值必须是唯一的。
Rule 8.13建议凡有可能，指针都应当指向带 const 限定的类型。
Rule 8.14必需不得使用 restrict 类型限定符。

初始化

编号分类准则
Rule 9.1强制具有自动存储期的对象，其值在设定之前不得被读取。
Rule 9.2必需聚合或联合的初始化器必须用花括号括起。
Rule 9.3必需不得对数组只作部分初始化。
Rule 9.4必需对象的同一个元素不得被初始化多次。
Rule 9.5必需使用指定初始化器初始化数组对象时，必须显式指定数组大小。

本质类型模型

编号分类准则
Rule 10.1必需操作数不得具有不适当的本质类型。
Rule 10.2必需本质字符型表达式不得以不适当的方式用于加法和减法运算。
Rule 10.3必需不得将表达式的值赋给本质类型较窄或本质类型类别不同的对象。
Rule 10.4必需对于实施通常算术转换的运算符，两个操作数必须具有相同的本质类型类别。
Rule 10.5建议不应将表达式的值强制转换为不适当的本质类型。
Rule 10.6必需不得将复合表达式的值赋给具有较宽本质类型的对象。
Rule 10.7必需如果实施通常算术转换的运算符以复合表达式为一个操作数，则另一个操作数的本质类型不得比该复合表达式的本质类型更宽。
Rule 10.8必需不得将复合表达式的值强制转换为不同的本质类型类别或较宽的本质类型。

指针类型转换

编号分类准则
Rule 11.1必需不得在函数指针与任何其他类型之间进行转换。
Rule 11.2必需不得在指向不完整类型的指针与任何其他类型之间进行转换。
Rule 11.3必需不得在指向某一对象类型的指针与指向不同对象类型的指针之间进行强制转换。
Rule 11.4建议不应在指向对象的指针与整数类型之间进行转换。
Rule 11.5建议不应将指向 void 的指针转换为指向对象的指针。
Rule 11.6必需不得在指向 void 的指针与算术类型之间进行强制转换。
Rule 11.7必需不得在指向对象的指针与非整数算术类型之间进行强制转换。
Rule 11.8必需强制转换不得移除指针所指类型上的任何 const 或 volatile 限定。
Rule 11.9必需宏 NULL 必须是整型空指针常量唯一允许使用的形式。

表达式

编号分类准则
Rule 12.1建议应明确表示表达式中运算符的优先级。
Rule 12.2必需移位运算符的右操作数必须在零至左操作数本质类型的位宽减一的范围内。
Rule 12.3建议不应使用逗号运算符。
Rule 12.4建议常量表达式的求值不应导致无符号整数回绕。

副作用

编号分类准则
Rule 13.1必需初始化器列表不得含有持久副作用。
Rule 13.2必需在所有允许的求值顺序下，表达式的值及其持久副作用都必须相同。
Rule 13.3建议完整表达式中如含有自增（++）或自减（--）运算符，除该自增或自减运算符引起的副作用外，不应再有其他潜在副作用。
Rule 13.4建议不应使用赋值运算符的结果。
Rule 13.5必需逻辑与（&&）或逻辑或（||）运算符的右操作数不得含有持久副作用。
Rule 13.6强制sizeof 运算符的操作数不得含有任何具有潜在副作用的表达式。

控制语句表达式

编号分类准则
Rule 14.1必需循环计数器不得具有本质浮点类型。
Rule 14.2必需for 循环必须具有规范的结构。
Rule 14.3必需控制表达式不得恒定不变。
Rule 14.4必需if 语句的控制表达式和迭代语句的控制表达式都必须具有本质布尔类型。

控制流

编号分类准则
Rule 15.1建议不应使用 goto 语句。
Rule 15.2必需goto 语句必须跳转到同一函数内在其后声明的标号。
Rule 15.3必需goto 语句所引用的任何标号，都必须声明在该语句所在的块内，或声明在包围该语句的某个块内。
Rule 15.4建议对任一迭代语句，用于终止该迭代的 break 或 goto 语句合计不应超过一条。
Rule 15.5建议函数应只有一个出口，且该出口应位于函数末尾。
Rule 15.6必需迭代语句或选择语句的语句体必须是复合语句。
Rule 15.7必需所有 if … else if 结构都必须以 else 语句结束。

switch 语句

编号分类准则
Rule 16.1必需所有 switch 语句都必须具有规定的结构。
Rule 16.2必需只有当最近一层包围它的复合语句就是 switch 语句体时，才允许使用 switch 标号。
Rule 16.3必需每个 switch 子句都必须以一条无条件的 break 语句结束。
Rule 16.4必需每条 switch 语句都必须有一个 default 标号。
Rule 16.5必需default 标号必须是 switch 语句中的第一个或最后一个 switch 标号。
Rule 16.6必需每条 switch 语句都必须至少含有两个 switch 子句。
Rule 16.7必需switch 的控制表达式不得具有本质布尔类型。

函数

编号分类准则
Rule 17.1必需不得使用 <stdarg.h> 提供的设施。
Rule 17.2必需函数不得直接或间接调用自身。
Rule 17.3强制不得隐式声明函数。
Rule 17.4强制对于返回类型非 void 的函数，每一条退出路径上都必须有显式写出的、带表达式的 return 语句。
Rule 17.5建议对于声明为数组类型的形参，对应的函数实参必须具有适当数量的元素。
Rule 17.6强制数组形参的声明不得在方括号 [ ] 之间包含关键字 static。
Rule 17.7必需返回类型非 void 的函数，其返回值必须被使用。
Rule 17.8建议不应修改函数形参。

指针与数组

编号分类准则
Rule 18.1必需对指针操作数进行算术运算所得的指针，必须指向与该操作数所指元素属于同一数组的元素。
Rule 18.2必需只有当两个指针所指的元素属于同一数组时，才允许将它们相减。
Rule 18.3必需不得对指针类型的对象使用关系运算符 >、>=、<、<=，除非这些指针指向同一个对象之内。
Rule 18.4建议不应对指针类型的表达式使用 +、-、+=、-= 运算符。
Rule 18.5建议声明中指针的嵌套不应超过两级。
Rule 18.6必需不得将具有自动存储期的对象的地址，复制到在该对象不再存在之后仍然存续的另一对象中。
Rule 18.7必需不得声明柔性数组成员。
Rule 18.8必需不得使用变长数组类型。

重叠存储

编号分类准则
Rule 19.1强制不得将一个对象赋值或复制给与其存储区域重叠的对象。
Rule 19.2建议不应使用 union 关键字。

预处理指令

编号分类准则
Rule 20.1建议#include 指令之前宜仅出现预处理指令或注释。
Rule 20.2必需头文件名中不得出现字符 '、"、\，也不得出现字符序列 /* 或 //。
Rule 20.3必需#include 指令之后必须是 <filename> 或 "filename" 形式的记号序列。
Rule 20.4必需不得定义与关键字同名的宏。
Rule 20.5建议不宜使用 #undef。
Rule 20.6必需宏实参中不得出现看起来像预处理指令的记号。
Rule 20.7必需宏形参展开后形成的表达式必须用圆括号括起。
Rule 20.8必需#if 或 #elif 预处理指令的控制表达式必须求得 0 或 1。
Rule 20.9必需#if 或 #elif 预处理指令的控制表达式中使用的所有标识符，在求值前都必须已由 #define 定义。
Rule 20.10建议不宜使用预处理运算符 # 和 ##。
Rule 20.11必需紧跟在 # 运算符之后的宏形参，其后不得紧接 ## 运算符。
Rule 20.12必需对于用作 # 或 ## 运算符操作数的宏形参，如果它本身还会进一步进行宏替换，则它只能用作这两个运算符的操作数。
Rule 20.13必需某行的第一个记号若为 #，该行就必须是一条有效的预处理指令。
Rule 20.14必需所有 #else、#elif 和 #endif 预处理指令，都必须与各自对应的 #if、#ifdef 或 #ifndef 指令位于同一文件中。

标准库

编号分类准则
Rule 21.1必需不得对保留标识符或保留宏名使用 #define 或 #undef。
Rule 21.2必需不得声明保留标识符或保留宏名。
Rule 21.3必需不得使用 <stdlib.h> 的内存分配和释放函数。
Rule 21.4必需不得使用标准头文件 <setjmp.h>。
Rule 21.5必需不得使用标准头文件 <signal.h>。
Rule 21.6必需不得使用标准库的输入／输出函数。
Rule 21.7必需不得使用 <stdlib.h> 中的 atof、atoi、atol 和 atoll 函数。
Rule 21.8必需不得使用 <stdlib.h> 中的库函数 abort、exit、getenv 和 system。
Rule 21.9必需不得使用 <stdlib.h> 中的库函数 bsearch 和 qsort。
Rule 21.10必需不得使用标准库的时间和日期函数。
Rule 21.11必需不得使用标准头文件 <tgmath.h>。
Rule 21.12建议不宜使用 <fenv.h> 的异常处理设施。

资源

编号分类准则
Rule 22.1必需通过标准库函数动态取得的所有资源都必须显式释放。
Rule 22.2强制只有经由标准库函数分配的内存块才可被释放。
Rule 22.3必需同一文件不得同时处于这两种打开状态：一个流允许读，另一个流允许写。
Rule 22.4强制不得尝试向以只读方式打开的流写入数据。
Rule 22.5强制不得对指向 FILE 对象的指针进行解引用。
Rule 22.6强制关联的流一经关闭，就不得使用指向该 FILE 的指针值。
