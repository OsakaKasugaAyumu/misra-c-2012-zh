配额模块能否用错误的配置构建？

main.c 请求 7 份配额，quota.c 的上限来自构建参数。把上限从 4 调到 17，再编译负责检查它的模块。

阅读对应准则译文自编源码验证记录证据边界

自编 C 示例（非原文）

main.c下载源码
/* 自编 C 示例（非原文） | Dir 2.1 | C90 / C99 */
#include "quota.h"
#include <stdio.h>

int main(void)
{
    const unsigned int granted = quota_take(7U);
    (void)printf("requested=7 granted=%u\n", granted);
    return (granted == 4U) ? 0 : 1;
}
quota.c下载源码
/* 自编 C 示例（非原文） | Dir 2.1 | C90 / C99 */
#include "quota.h"

#ifndef QUOTA_LIMIT
#error QUOTA_LIMIT must be supplied by the build
#elif QUOTA_LIMIT < 1 || QUOTA_LIMIT > 16
#error QUOTA_LIMIT must be in 1..16
#endif

unsigned int quota_take(unsigned int requested)
{
    return (requested < QUOTA_LIMIT) ? requested : QUOTA_LIMIT;
}
quota.h下载源码
/* 自编 C 示例（非原文） | Dir 2.1 | C90 / C99 */
#ifndef TEACHING_QUOTA_H
#define TEACHING_QUOTA_H
unsigned int quota_take(unsigned int requested);
#endif

怎么验证，观察到了什么？

正常构建分配 4 份；第二次编译在 quota.c 的预处理检查处停止。对照命令中的源文件和宏值，比单看一个成功退出码更有用。

复现方式：保存本页各源文件，保持文件名和子目录不变，在它们的共同根目录按顺序执行。记录环境：GCC 13.4.0 / x86_64-pc-cygwin。下列为实际退出码；诊断只摘与实验相关的行。符号 $ 表示命令提示符，不必输入。

$ gcc -std=c99 -pedantic-errors -Wall -Wextra -O0 -DQUOTA_LIMIT=4U main.c quota.c -o demo

实际退出码：0 · 符合预期

$ ./demo

实际退出码：0 · 符合预期
标准输出：

requested=7 granted=4
$ gcc -std=c99 -pedantic-errors -Wall -Wextra -O0 -DQUOTA_LIMIT=17U -c quota.c -o unit.o

实际退出码：1 · 预期拒绝（不运行）

诊断要点：

quota.c:7:2: error: #error QUOTA_LIMIT must be in 1..16
