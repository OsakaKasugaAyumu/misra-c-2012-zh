实验 36 / 46　·　Rule 5.6

两个文件里的 typedef 究竟来自哪一处？

count.h 的同一声明同时用于两个翻译单元。区分相关联的标记名与 typedef 名，再检查对照中 main 声明的同名对象。

阅读对应准则译文自编源码验证步骤证据边界

unsigned int spool_read(void) { spool_count s = {7U}; return s.turns; }

实际观察与审查依据

两个版本都能构建。对照版里同名的局部对象不是头文件中的类型别名；单看程序的退出码分辨不出这一区别。

  • count.h:spool_count（标记／typedef，文件作用域）：同一类型的关联标记和 typedef 同名；两次包含来自同一处定义。
  • check.c:main（普通对象，块作用域）：对照的 spool_count 不是该 typedef，而是局部对象；正常版用 measured。

证据边界

头文件来源和声明身份说明了为什么有些重复是允许的。程序都能读到 7，不代表额外定义的普通对象可以占用 typedef 名。
