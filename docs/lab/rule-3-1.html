实验 27 / 31　·　Rule 3.1

注释跨过赋值后，变量还会被更新吗？

两份程序都写有 stage = 6。对照文件提前打开块注释，让这一行变成了注释内容。

阅读对应准则译文自编源码验证记录证据边界

自编 C 示例（非原文）

compare.c下载源码
/* 自编 C 示例（非原文） | Rule 3.1 */
int main(void)
{
    int stage = 0;
    /* begin note
    stage = 6;
    /* end note */
    return stage == 6 ? 0 : 1;
}
demo.c下载源码
/* 自编 C 示例（非原文） | Rule 3.1 */
int main(void)
{
    int stage = 0;
    /* begin and end note */
    stage = 6;
    return stage == 6 ? 0 : 1;
}

怎么验证，观察到了什么？

对照版本可以生成可执行文件，却因为 stage 仍为 0 而以 1 退出。把两个文件的注释起止符逐一配对即可定位原因。

复现方式：保存本页各源文件，保持文件名和子目录不变，在它们的共同根目录按顺序执行。记录环境：GCC 13.4.0 / x86_64-pc-cygwin。下列为实际退出码；诊断只摘与实验相关的行。符号 $ 表示命令提示符，不必输入。

$ gcc -std=c99 -pedantic-errors -Wall -Wextra -O0 demo.c -o demo

实际退出码：0 · 符合预期

$ ./demo

实际退出码：0 · 符合预期

$ gcc -std=c99 -pedantic-errors -Wall -Wextra -O0 compare.c -o demo

实际退出码：0 · 符合预期

诊断要点：

compare.c:7:5: warning: "/*" within comment [-Wcomment]
$ ./demo

实际退出码：1 · 预期观察到对照差异

证据边界

这里展示的是这个文件中的注释边界，不是说凡是有注释警告都会改变程序输出。
