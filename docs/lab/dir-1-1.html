为什么空槽有时变成了已占用？

同一份 slot.c 把 -1 存进普通 char，再根据读回的数值判断槽位。两次构建只改变 char 的符号选项。

阅读对应准则译文自编源码验证记录证据边界

自编 C 示例（非原文）

slot.c下载源码
/* 自编 C 示例（非原文） | Dir 1.1 | C90 / C99 */
#include <limits.h>
#include <stdio.h>

#if UCHAR_MAX > INT_MAX
#error This example needs int to represent every unsigned char value
#endif

static const char *label(int sample)
{
    return (sample < 0) ? "missing" : "present";
}

int main(void)
{
    const char empty_slot = (char)-1;
    const char filled_slot = (char)0;
    (void)printf("CHAR_MIN=%d; empty=%d:%s; filled=%d:%s\n",
                 (int)CHAR_MIN, (int)empty_slot, label((int)empty_slot),
                 (int)filled_slot, label((int)filled_slot));
    return 0;
}

怎么验证，观察到了什么？

对照两行 CHAR_MIN 和 empty：一次读到 -1，另一次读到 255。要复现这个现象，除了源码，还得记录目标和编译选项。

复现方式：保存本页各源文件，保持文件名和子目录不变，在它们的共同根目录按顺序执行。记录环境：GCC 13.4.0 / x86_64-pc-cygwin。下列为实际退出码；诊断只摘与实验相关的行。符号 $ 表示命令提示符，不必输入。

$ gcc -std=c99 -pedantic-errors -Wall -Wextra -O0 -fsigned-char slot.c -o demo

实际退出码：0 · 符合预期

$ ./demo

实际退出码：0 · 符合预期
标准输出：

CHAR_MIN=-128; empty=-1:missing; filled=0:present
$ gcc -std=c99 -pedantic-errors -Wall -Wextra -O0 -funsigned-char slot.c -o demo

实际退出码：0 · 符合预期

$ ./demo

实际退出码：0 · 符合预期
标准输出：

CHAR_MIN=0; empty=255:present; filled=0:present

证据边界

这里只测了当前 GCC 目标的两种配置；不能把其中一个 char 范围写成所有设备的约定。
