为什么漏掉头文件，单独编译仍能过？

先对照 tabs.h、tabs.c 与 no_prior.c。前两者让共享原型和定义在同一个编译单元相遇；最后一个文件只有定义，没有包含共享原型。

#include <stdio.h>

怎么验证，观察到了什么？

正常版本通过四个输入。单独编译 no_prior.c 时，普通选项返回 0；加上 -Werror=missing-prototypes 后被拒绝。两次都不链接、不运行它。

复现方式：保存本页各源文件，保持文件名和子目录不变，在它们的共同根目录按顺序执行。记录环境：GCC 13.4.0 / x86_64-pc-cygwin。下列为实际退出码；诊断只摘与实验相关的行。符号 $ 表示命令提示符，不必输入。

$ gcc -std=c99 -pedantic-errors -Wall -Wextra -O0 -Werror=missing-prototypes reader.c tabs.c -o demo

实际退出码：0 · 符合预期

$ ./demo

实际退出码：0 · 符合预期
标准输出：

tab checks: 4/4 passed
$ gcc -std=c99 -pedantic-errors -Wall -Wextra -O0 -c review-only/no_prior.c -o unit.o

实际退出码：0 · 符合预期

$ gcc -std=c99 -pedantic-errors -Wall -Wextra -O0 -Werror=missing-prototypes -c review-only/no_prior.c -o unit.o

实际退出码：1 · 预期拒绝（不运行）

诊断要点：

review-only/no_prior.c:3:14: error: no previous prototype for 'tab_for_card' [-Werror=missing-prototypes]

证据边界

这表明诊断取决于可见声明和编译选项。它没有证明普通编译会发现跨文件类型冲突；严格选项也不能证明原型一定来自项目指定的头文件。
